第 0 章

开场白:train 是一座"缺陷驾校"

对应 README 开头「train —— 多点位单模型缺陷分割训练」
📖 先听个故事

上一本《synth_assets 图解手册》讲的是"兵工厂"——量产缺陷素材。素材攒够了,该让"新兵"上场学本领了:教会一个 AI 模型看一眼金属零件照片,就把缺陷的准确位置圈出来(这项活叫"缺陷分割")。这就是 train 仓库的使命。

教学有个老大难:缺陷是稀罕物,真图没几张。train 的妙招是"现场出题":拿现场的干净大图当卷子,随机把合成缺陷贴上去(贴得光影自然,像真长出来的一样),贴哪儿就教模型"哪儿是缺陷"。相当于驾校在自己场地上摆锥桶练车——锥桶想摆多少摆多少。

但光练不行,还得真考:每个点位 val/ 子目录里人工手工放入的真实缺陷考卷(整张图从不进训练)——模型考得好不好,看的全是它没见过的真缺陷。考得最好的那一轮权重,成为唯一交付的 best 模型,连同推理所需的配置一起打成 deploy/ 推理包。

还有个关键词叫"多点位单模型":一个产品的全部相机机位(点位)不各训各的,而是混在一起训成一个模型——一个产品只交付一个模型文件。

这本手册怎么读?

  • 每章对应 README「宏观大流程」的一个环节,并补充了源码里的真实细节(常量、公式、坑);
  • 看不懂的词随时回第 1 章词表;绿色小方块 512 是关键数字,第 13 章有完整速查表;
  • 四色提示框:💡蓝色=大白话比喻,🎯绿色=为什么这么设计,⚠️黄色=注意/坑,📖紫色=故事;
  • 与《synth_assets 图解手册》是姊妹篇:素材从哪来、泊松贴图的底层细节,那本讲得更细,本册自包含但点到即止。
第 1 章

新手词表:先搞懂这些词,后文畅通无阻

README 与 train 源码里出现的所有"黑话",按主题分组

🖼️ 看图与数据

点位产线上相机机位的编号(如 JXFB-1-P1、JXFB-1-P5),一个点位一个文件夹,内放该机位拍的原图。
基准图 {基准图名}.bmp每个点位选定的"标准照片",配套 {基准图名}.json 分区定义。全点位其他照片都要向它"对齐看齐"。
分区基准图上人工画好的区域(存于 json),如「加工面」= 允许出现缺陷、需要检测的区域。
domain 分区一种特殊分区,名字必须叫 "domain",专供对齐使用——只有这个分区里的图像内容参与位置匹配,夹具、背景、反光都不算数。每个点位必备。
检测区 / 有效检测区基准图上人工画的分区,经逆向投射 + ±10px 边缘吸附落到每张照片上,就是该图的"有效检测区"——训练与考试只在这块区域内出题/算分,区外一律不管。
NG 图 / OK 图NG = 带真实缺陷的照片(.tmp 标注里有 label ≠ "排除" 的多边形);OK = 干净照片(无标注,或只标了「排除」)。两种图都入训练池:NG 图贡献缺陷实例(抠真实小图、训 LoRA),但沾到标注的切块会被训练整块跳过;独立考卷单独放 {点位}/val/。
val/ 独立考卷 · 早停集考卷 = {点位}/val/ 目录里人工手工放入的真缺陷图,绝不进训练池;训练池 8:2 分出的固定小题集(每点位 ≤10 张)叫早停集,只用来算 val_loss 判"要不要继续练"。
命中数(hit_defects)与综合质量分考试指标:每个标注多边形与报警交集 ≥1px 记"命中 1 个";best 按 quality_score = 命中数×3000 + 总交集像素 − 0.05×标注外误报像素 择优——召回优先、定位准、误报还要少。
真实小缺陷图(real_*.png)从原图原生像素上抠出的小图 + 掩码(非 512,四周留 8px):完整保留人工标注轮廓(贴边缺陷不沿分区边界腰斩),掩码外像素优先填小图局部「有效检测区 ∩ 环带」的灰度中值——零插值失真,是规格测算、LoRA 形变模板与贴题的"真样本源",按 patches/{检测区}/{缺陷}/ 归档。
合成小缺陷图(synth_*.png)内置 FLUX LoRA 在目标产品自己的底图上重绘假缺陷、双阈值差分抠出的小图 + 掩码(非 512),与真实小图同池平权混用,同存 patches/{检测区}/{缺陷}/;形状模板取自真实缺陷掩码的洗牌轮转 + 随机弹性形变。
干净切块(不净化)系统对底图零修补、零扭曲(全程不做 inpaint):切块时把沾到任何标注(含外扩 4px)或不含有效检测区的 512 块整块跳过——留下的每一块都是 100% 无瑕的原始相机像素。
.tmp 标注与原图同名的多边形标注文件(标注工具「老表,标我.exe」绘制);label 为「砂眼」「划痕」等 = 真缺陷,「排除」= 刻意忽略的区域(如反光亮斑)。
切块(tile)模型一次只"看" 512×512 的小块;整张大图按网格切成许多块分别推理,再拼回整图。stride(步长)384 = 相邻块错开 128px 重叠。
热力图模型对整图每个像素的"是缺陷"打分(0~1),画成一张温度图——越亮越像缺陷。超过 0.5 就报警。
GT 标签(真值)训练时告诉模型的标准答案图:缺陷 = 1,正常背景 = 0,不用学的地方 = 255(忽略)。
总交集考试分数:所有考卷上「模型报警像素 ∩ 人工标注像素」的总面积。双方都用实际形状,不用外接方框。

🧭 对齐相关

对齐(逆向精对齐)相机每次拍的位置总有毫米级偏差。与"把照片掰正"相反,这里照片一张都不动:解出"基准图 → 照片"的单应 H,把基准图上的分区逆向投射到每张照片上,再经 ±10px 边缘吸附得到各自的"有效检测区"——原图始终保持 100% 原始像素。
±10px 边缘吸附刚性投射后,分区边界与照片上真实的零件边缘往往差几像素:沿轮廓法向在 ±10px 内找灰度梯度最大的真实边缘"吸"过去(支持带孔洞与孔内凸台的复杂嵌套拓扑),这就是"二次精对齐"。
Harris 角点图像里"往哪个方向看都在变"的点(拐角、交界处),是匹配两图位置的锚钉。怎么算出来的、为什么非它不可?见 6.2 开头的三格图解。
RANSAC"少数派报告"式稳健匹配:拿角点配对猜变换,大多数配对都认同的那个才采信,个别错配直接出局。
单应矩阵 H(8 自由度)一张 3×3 的"坐标换算表",能表达平移+旋转+缩放+透视歪斜,把一张图的位置换算到另一张图。
内点(inliers)认同最终变换的角点配对数,少于 50 个判定对齐失败——阈值从严,几十对都点头才敢信,偶然凑对的脆弱变换直接出局。
紧贴区 vs 圆滑区同一张照片的有效检测区做两版:紧贴版(训练/贴图用)直接吸在真实边缘内侧,保证切出的底图块 100% 干净;圆滑版(推理与缺陷归属用)对轮廓圆滑架桥,跨过手画锯齿与边缘缺口——贴边缺陷、崩边不被漏掉,也不会误入相邻区。
距离变换给分区每个点算"到分区边界有多远"的距离地图;智能放置靠它找近边带、开阔地和孔心。

🎓 训练相关

模型 / 权重模型 = 会看图的"电子大脑";权重 = 脑内亿万数字旋钮。训练就是反复做题拧旋钮。best_int…_.pth 就是存旋钮的文件。
EfficientViT-SAM L1官方预训练的视觉骨干网络(SA-1B 数据集热启动),train 拿它当"底子"再改造,不从零学起。
骨干 / 冻结骨干 = 模型前端负责"看懂纹理"的大层。冻结 = 这些旋钮锁死不动,保住预训练的通用眼力。
LoRA(分割侧)给冻结的卷积层外挂小旁路(r=16,零初始化起步),只训旁路——小数据微调不伤底子。与 synth_assets 里的 LoRA 同思想、不同对象。
Focal 损失给"稀少的缺陷像素"加权打分的损失函数——缺陷只占画面零头,不加权模型会摆烂全答"正常"。
Dice 损失衡量"圈出来的形状和答案重合度"的损失(1 = 完美重合),和 Focal 加在一起用(权重 ×3)。
PointRend?已退役早期版本训练损失用 PointRend 智能采样(抽点、75% 挑最不确定处)省算力;新版为让训练与验证同尺同构、跨轮可比,训练与验证统一改为全像素稠密 Focal+Dice(自动屏蔽 255)。
epoch(轮)把训练题集完整过一遍 = 1 轮;上限 20 轮,练满 8 轮后允许早停。
统一注水预算 + 牌靴出题账本:按背景域 (点位, 检测区) 的干净块数 T 与缺陷种数 D,以权重 √(T×D) 在上下界内"注水"分配单轮正样本配额,正负严格 1:1;每个 (检测区, 缺陷) 的素材池配一只无放回洗牌牌靴——每张真实/合成小图都发过一轮牌才重新洗,绝无素材闲置。
batch一次同时喂给显卡的图块数。不手填——按显存自动算(显存 GB ÷ 3,夹在 8~16)。
学习率 / 热身 / 余弦每步拧旋钮的幅度。先线性热身(1 轮,从小步开始),再按余弦曲线缓缓收小。
val_loss 与早停每轮在固定验证题集上算损失;练满 max(8, 分片数) 轮后连 4 轮不降(降幅超 2e-3)就提前收工,防过拟合。
EMA(近期平均权重)另存一份"滑动平均"的权重(decay 0.999)——把近期每步的抖动平均掉,验证/考试/交付全用这份,口径统一。
bf16低精度记数法,省显存提速;指数位与 fp32 相同,不会下溢,无需损失缩放。
DDP 多卡多张显卡分工并行训练,共享同一注水预算与牌靴(无放回发牌序号跨卡完全一致);考试只由 0 号卡独占执行,阶段 1 的 LoRA 训练也吃多卡并行。
迁移 / 精调(--base)不从头学,拿现成权重当起点:官方骨干,或自家/他产品的 best_*.pth。

🧩 图像处理手法

泊松融合(零光晕)把缺陷的明暗残差"解方程"融进底图(NORMAL_CLONE);残差 = 50% 泊松 + 50% 素材原生,只在缺陷标签内部落笔——正常背景(label=0)一个像素都不被改写,无光晕污染。
内部腐蚀 4pxOpenCV 泊松底层会偷偷把掩码向内啃 4px——所以送入前必须先外扩 5~7px 保住缺陷边缘梯度。
柔边回写泊松残差不整块照抄:缺陷标签外圈 1px 权重 0.55、往内 ≥2px 即满幅 1.0;在 label=0 处权重恒为 0——缺陷贴得牢,背景纹丝不动。
对数均匀抽样在 [min, max] 里抽目标大小时"每个数量级等概率"——普通均匀抽样会让大缺陷霸屏,小砂眼几乎抽不到。
上下文画布贴缺陷不止贴在 512 块内,而是贴在「块 + 四周一圈真实底图」的大画布上再裁回——跨块缺陷也能完整融合。
边缘复制填充旋转素材时,空出来的角落用边缘像素复制填满,避免黑角混进内容。
重叠窗加权拼接整图切块推理后,相邻块 128px 重叠带按"此消彼长"的线性权重窗拼回,块边(最不准处)自动降权,热力图无拼缝。
INPAINT?已全面退役早期版本用它修补底图真缺陷、LoRA 图块内其他标注;新版判定风险大于收益——底图零净化(脏块直接跳过)、LoRA 图块内其他标注直接置损失权重 0,全程不再做任何修补。

🎯 不用再准备缺陷素材和绑定表了?

老版要人工抠 assets/{缺陷类型}/ 素材对、手写 assets.jsonc 绑定表(哪个分区贴哪类缺陷、尺寸范围多少)。新版把这些全部自动化:真实小缺陷图直接从 NG 原图上抠(patches/…/real_*.png),合成小缺陷图由内置 FLUX LoRA 现场量产(patches/…/synth_*.png),"哪个检测区有哪些缺陷"由圆滑有效检测区 ∩ 标注多边形的交集面积自动归属,"贴多大、多深"由训练池实测统计自适应——人只剩"放原图、画分区"两件事,连数量参数都没有。

规格全自动测算:auto_zones.json 代替 assets.jsonc

启动后系统会为每个 {检测区}/{缺陷} 组合自动算一份实测规格(存 .tmp/{产品}/auto_zones.json,即代码里的 mat.assets_cfg),造题全部照它执行:

  • 面积规格 [min, max, med]:全部真实实例面积的 p2 分位 ×0.75 ~ p98 分位 ×1.30(下限保底 18px),中位数 med 夹在区间内;
  • 对比度分布 [diff_lo, diff_med, diff_hi]:外扩 2~7px 干净环带测出的 |缺陷−背景| 的 p10 ×0.85(下限 16)~ 与「diff_lo×1.35 和 p90×1.15 取大」(上限 195),中位数 diff_med 一并记录;
  • 明暗极性 polarity:实测该组缺陷整体偏暗 / 偏亮 / 混合——造题贴图时保持原生明暗方向(暗坑不画成亮斑);落位固定区内 / 区边缘五五分(50%/50%);
  • 归档粒度:所有规格、真实与合成小图统一按 {产品}/{检测区}/{缺陷} 三级目录管理——同名检测区(如都叫"加工面")跨点位、跨 --reuse 产品合并共享。
💡 大白话:为什么要"掐头去尾"?

给全班订校服,不能按个子最高的篮球生和最矮的同学定尺寸——区间会被撑爆。所以先把两头最极端的各掐掉一小撮(百分位 p2/p98 就是"排序后第 2%、98% 位置的值",一百颗里排第 2 名和第 98 名的水平),区间立刻回到"正常人群";再各放宽一档(下端 ×0.75、上端 ×1.30),给少数天生偏大偏小的真缺陷留件能穿的衣服;最后的"夹逼"(面积下限 18、对比度 16~195)是双保险——实例太少、量得不稳时,区间既不会塌成一点,也不会飞出物理合理的范围。

💡 大白话

这张"规格单"不是人写的,是程序量出来的:把训练池里每个真缺陷量一遍个头(面积)、深浅(对比度)、明暗方向(极性),按百分位折出合理区间——真实缺陷多大,合成题就贴多大;真实多深,贴出来就多深;真实偏暗,贴出来绝不发亮。新标一批缺陷照片,下次启动规格自动刷新,无需任何手动维护。

⚠️ 两个易错点

① 判一张图是不是 NG(带缺陷),看的是 .tmp 里有没有 label ≠ "排除" 的多边形——只标了「排除」的图算 OK 干净图(「排除」区在考试计分时同样从有效检测区中扣除);② 每个 (检测区, 缺陷) 组合的训练池实例(含 --reuse 复用)必须 ≥4 个——全局每类缺陷也要 ≥4;不足时启动即红字退出,因为规格测算和每个组合一支的专属 LoRA 都撑不起来。

  • batch = 显存 GB ÷ 3,夹在 8~16;

第 4 章

训练事件线总览:一条命令的旅程

对应 README §一「宏观大流程」:五件核心大事

敲下 uv run train,程序自动走完五件大事(标 ⚡ 的环节带开局指纹检测——素材没变就秒级跳过)。先看全景图,再逐站配图细看:

1. ⚡ 素材体检 + 开局跳过检测 checkup.py + prep_plan.py

  • 校验分区 json(含 domain + ≥1 检测分区)/ 基准图在场 / 全点位同分辨率 / 标注可解析;
  • 盘点训练池(根目录 OK+NG)与 val/ 独立考卷;体检通过后立刻做开局指纹检测(prep_plan):一次性比对逆向对齐/真实小图/LoRA/合成四环节的输入指纹,没变的直接跳过;
  • 全局每类缺陷、以及每个 (检测区, 缺陷) 组合的实例都要 ≥4 个,不足红字退出;不合格直接退出,绝不代建。

2. ⚡ 逆向精对齐与真实小图 align.py

  • 用 domain 分区角点解算"基准图 → 照片"的单应 H,照片原图一律不动(零透视变形、零净化);
  • 分区蒙版按 H 逆向投射到每张照片,再经 ±10px 边缘吸附得到"有效检测区"(训练用紧贴版,推理/归属用圆滑版);
  • 对齐失败图成对移入 align_failed/ 隔离并记 moved.jsonl,红字退出;
  • 缺陷按圆滑区最大交集归属 {检测区}/{缺陷},从原图零失真抠出真实小图(外扩 8px + 局部中值去背景),顺带实测规格(面积/对比度/极性)。

3. ⚡ 阶段 1 LoRA 训练 + 阶段 2 小图池 lora_synth.py

  • 阶段 1:每个 {检测区}/{缺陷} 组合单独训一支专属 LoRA(1000 步,多卡并行);训练图块围绕真实缺陷裁剪、目标凑 60 张(k=⌈60÷实例数⌉ 夹 1~4,上限 240)——不做任何修补:块内其他标注直接置损失权重 0,目标缺陷直接外扩 8px 软权重(1.0→0.4);
  • 阶段 2:真实小图从原图抠取;合成小图按统一预算同源导出的配额 Q_synth = clip(⌈Σ(E÷D)÷5⌉, 60, 600) 用 LoRA 重绘——形状模板取自真实掩码的洗牌轮转 + 随机弹性形变,只在目标产品自己的底图上重绘(--reuse 产品只出真图,不当画布);
  • 重绘前后双阈值差分抠出合成小图,与真实小图同存 patches/{检测区}/{缺陷}/(外扩 8px + 中值去背景,同池平权)。

4. ⚡ 统一预算:8:2 分卷 + 注水配额 budget.py

  • 训练池(全部合格图)按 8:2 分训练底图 / 早停集(每点位 ≤10 张;全产品验证干净块全局封顶 1200,防百点位验证超时);
  • 预切统计每个 (点位, 检测区) 的干净块数 T(跳过含标注块)与缺陷种数 D,按权重 √(T×D) 在上下界内"注水"分配单轮正样本配额 E——小区保底 100×D、单块最多重复 5 次、单轮全产品 ≤16000;
  • 超大检测区自动拆 num_shards 分片跨轮轮转(轮转完毕前早停不生效);正负 1:1;合成配额 Q_synth 由 E 同源导出。

5. 阶段 3 分割训练与考卷验收(上限 20 轮;早停:练满 max(8, 分片数) 轮后 val_loss 连续 4 轮不降)

  • 训练图块全部从原始 .bmp 直裁(零净化):沾到任何标注(含外扩 4px)或不含有效检测区的块直接跳过;
  • 每轮在线造题:注水配额出题正负 1:1;多区逐区贴图,每 (检测区,缺陷) 一只无放回牌靴(真实 + 合成平权),区内/区边缘五五分、零光晕泊松,区内 0/1、区外 255(细节在第 8 章);
  • [训练]:EfficientViT-SAM L1 + LoRA + 级联浅层跳连分割头(Focal+Dice,bf16,EMA);
  • [验证早停]:固定早停题集全像素稠密算 val_loss,决定是否早停;
  • [考卷考试]:val/ 考卷按圆滑有效检测区(扣除「排除」区)切块推理(重叠带加权窗拼接)→ 阈值 0.5 算总交集、命中数与综合质量分(检出×3000 − 0.05×误报),择优交付 best + deploy/。
💡 大白话

整条事件线像办一场规范的考试周:先查证件(体检)→ 把标准地图誊到每位考生的桌面上并对每位考生的错题建档(逆向对齐 + 真实小图)→ 照着错题给每种题量产模拟锥桶(专属 LoRA + 合成小图)→ 排课程表(统一注水预算)→ 白天在 100% 干净的原始场地上刷题、晚上小测,练到进步停滞就停(训练+验证)→ 期末卷打分,历史最高分留档(考试+best)。而且全程有个"班主任直播间"(监控 web 8300)可以围观。①~③ 都是 ⚡ 指纹可跳过的——素材没改时,第二次启动直接从刷题开始。

第 6 章

逆向精对齐:照片不动,把"标准地图"誊到每张照片上

对应 README 宏观大流程 1(体检与逆向精对齐)+ align.py 源码

6.1 为什么必须对齐?对齐到底"改"了什么?

相机每次拍照,工件位置总有毫米级偏差(挪了一点、歪了一点)——同一块金属、同一道划痕,在不同照片里落在不同的像素位置上。这会直接毁掉训练,先看会发生什么:

💡 大白话:一张平面图,几百种摆法

分区像一张只画了一次的考场平面图,要套到几百张摆法各不相同的照片上用。不配"换算表"就硬套,同一块地盘在 A 图罩住加工面、在 B 图罩住隔壁的槽——考场自己先乱了。对齐就是给每张照片解一份专属换算表 H,把平面图按这张照片的摆法誊一份再贴上去,并吸附到零件真实边缘——同一块物理地盘,在每张照片里都被同一套"有效检测区"罩住,而照片本身一个像素都不用动。

对齐 = 给每张照片解一份"坐标换算表" H(基准图 → 照片),把基准图上画的分区逆向投射到照片上,再吸附到零件的真实边缘,得到这张照片专属的"有效检测区"——照片本身一个像素都不被改动(怎么找角点、怎么解这份换算表,见下一节 6.2)。

🎯 为什么说对齐是"地基"?全图训练不行吗?

模型认的是"样子"——划痕挪几十个像素它照样认得。所以如果全图当考场、标注跟着各自的照片走,原理上确实能训。但 train 这套系统是"分区画一次、自动出题、自动判卷"的自动化设计:分区在基准图上画一次就要套用几百张照片,假缺陷按分区坐标自动贴、贴哪儿答案就自动生成在哪,成绩按坐标逐点比——而零件每张照片都挪几毫米,不对齐这些环节全会错位。

改走全图路线的代价:检测范围要么逐张照片手工画(几百张图 × 几十个点位,工作量爆炸),要么把夹具、深槽、反光全当"正常"教(误报温床);同时放弃自动贴题,还要多几倍数据才补得回"位置记忆"这条线索——对齐后同一位置在每张图里都是同一块金属,模型能记住"这里平时长什么样",9~13 像素的小砂眼全靠它救命。所以工程上,对齐是最便宜的那块地基。

那对齐到底"改"了什么?——连副本都不生成:照片零扭曲、零净化,训练与考试全程直接消费原始 .bmp。对齐的产物只有一样东西——一本轻量台账 align.json:

  • 每张照片一条记录:装着它的坐标换算表 H(3×3 矩阵)与各区"有效检测区"的压缩蒙版(zb64 RLE);
  • 照片与标注原件:一个字节不动;考试直接在 val 原图上推理,老师画的圈也在原图上——无需任何搬运;
  • 基准图与分区 json:一个字节不动;需要时按 H 把分区"誊"到某张照片上用(逆向投射,专图见 6.3 细节⑤)。

所以这套"逆向对齐"比"把照片掰正"的老思路更彻底地保护原始数据:不掰正、不修补、不复制大图——只留一本台账。

💡 大白话:档案馆只发复印件

把对齐想成一座档案馆:现场照片是原始档案,永远锁在柜里不动、不复印、不修补;馆里唯一的"标准地图"(基准图分区)也从不改。馆员对每张照片只做一件事:把标准地图按这张照片的摆法誊一张同样歪的小样收进台账(逆向投射 + 边缘吸附),以后要在哪张照片上圈地盘,翻台账就行。训练、考试都直接看原件——台账只是目录,原件才是教材,所以对齐参数改了、重跑对齐,都不会弄丢或污染任何原始数据。

6.2 怎么对齐:角点配对 + 稳健解算

讲配对之前,先把地基打好——角点 = 画面里"往哪个方向看都在变"的点,也就是各种拐角、交界的位置。Harris 检测的思路很直白:拿一个小窗口框在每个像素上,问一句"把窗口往任意方向挪一点,里面的内容变不变?"——两个方向都变的,就是角点。

💡 大白话:认人靠痣,不靠"有皮肤"

平坦区像一面空墙,没有任何记号;边缘像一条长长的线,线上每个点长得一模一样,挪一挪就认不出谁是谁;角点像墙角的插座、脸上的痣——独一无二,一眼锁定。基准图和待测图要认出"同一个点"来配对,靠的正是角点这种"胎记":配出几十对,才能解出单应 H 那张坐标换算表。金属表面看着平,放大全是刀纹、螺纹、微坑,微观拐角遍地——所以角点管够,还嫌多(所以才要 6.3 的"每格取最强 30 个"限额)。

地基打好,回到正题。对齐器与 define_masks 的对齐实验完全同款(Point8DofAligner,全程 Halcon 原生算子)。具体用到的技术依次是:points_harris 找角点(只在 domain 分区内)→ 分 6×6 格、每格取最强 30 个 → proj_match_points_ransac 稳健配对解单应(NCC 灰度匹配、匹配掩窗 10px、gold_standard 精解、内点距离阈 1.5px、搜索容差 80px、随机种子 42 固定可复现);内点不足 50 个直接判失败(阈值从严,防偶然凑对)。解出 H 后不回贴照片——只把分区蒙版逆向投射到照片、再做 ±10px 边缘吸附,生成"有效检测区"。

💡 大白话:单应矩阵 = 一张"透明胶片摆放说明书"

想象把待测图印在一张透明胶片上,要摆到基准图上严丝合缝——可以平移、旋转、均匀放大缩小,还能透视歪斜(近大远小那种斜)。这几类动作合起来正好 8 个自由度;单应矩阵 H 就是那张 3×3 的"摆放说明书":给它一个基准图坐标,它告诉你该去待测图哪个位置取样。

💡 大白话:RANSAC = 少数派报告出局

角点配对里难免混进错配——两处长得很像的刀纹认错了人。RANSAC 的玩法像投票听证:随机抽几对配对试算一个变换,然后让全体配对投票——按这个变换换算后仍对得上的算"认同票";反复试、取认同票最多(内点最多)的变换当选,投反对票的错配直接出局。所以个别认错人,带不偏最终结果。

💡 大白话:同一张地图,训练版"抠门",考试版"大方"

紧贴版像个抠门的质检员——宁可少圈一圈,绝不把区外杂色带进考场(脏一点就等于教错课);圆滑版像个大方的验收员——锯齿抹平、缺口架桥,宁可多圈一点,也不能漏掉贴着边长的缺陷(否则考试时贴边真缺陷被划到区外,模型报了也不算分,白白冤枉)。两个版本各有各的场合,都记在同一本 align.json 台账里。

6.3 源码里的工程细节(逐条图解)

先给五条细节记一句口诀:快、匀、稳、省、准——每条解决对齐环节里的一个具体毛病:

细节作用(一个字)大白话没有它会怎样
① 结构尺度快 + 准粗活(找点、配对、解单应)在缩小图上干,又快又稳;真正"搬像素"时换回原图,清晰度一点不丢对齐一张图要很久,还容易错配
② 分网格均匀采样匀角点天然扎堆在花纹多的地方;每格限额后格格有锚钉,解出的变换对整幅图负责变换只迁就扎堆的一小块,远处区域全贴歪
③ 合理性检查稳给解出的变换当"安检门"——跑飞的(位移过大/缩放离谱)直接拒绝错配点把解算带偏,照片被贴到九霄云外,悄悄毒化数据
④ 开局跳过检测省开局一次性比对四环节指纹(对齐按点位、LoRA/合成按 区,缺陷)——没变的直接复用 align.json / patches/ / LoRA 权重,合成可留旧补差;跨会话也保留调整一个训练参数也要几百张图全部重做前置,白白浪费几十分钟
⑤ H 方向口径准一张"查址表"定死两个方向:回贴顺着查、搬标注逆着查,全工程统一方向用反,图和标注一搬就歪,考试计分全错还难排查
💡 大白话:一条流水线的五道工序

把五条串起来看,就是给"把几百张现场照片摆进同一张标准地图"这条流水线装的五道工序:先用小图快速找到锚钉(快),再把锚钉铺满全图(匀),解出的变换过一遍安检(稳),结果存档反复用(省),最后所有搬运统一方向(准)。少了任何一道,照片要么摆得慢、要么摆得歪、要么搬丢了。

细节① 结构尺度:找点用小图,吸附用大图

直接在几千像素的大图上找角点、配对,又慢又容易错配。做法是先等比缩到宽 512(结构尺度)把"找点 + 配对 + 解单应"全干完,再把解出的单应换算回全分辨率——分区投射与 ±10px 边缘吸附直接在原图分辨率上进行,精度一点不丢。搜索容差默认 80px:每个基准角点只在邻域 ±80px(按尺度折算)内找待测伙伴;待测图偏移大时可在 json 的 align 段加大。

细节② 分网格均匀采样:36 格 × 每格 30 个,全图都有锚钉

Harris 角点天然"扎堆"——亮纹理、花纹多的地方一口气冒出几百个,平整区域一个没有。把图分成 6×6 格、每格只取响应最强的 30 个,保证每个角落都有锚钉,解算的单应才对全图负责。

细节③ 合理性检查:防"匹配跑飞"

解出的单应先过两道体检:四角最大位移 ≤ 图边长的 15%、缩放行列式 det ∈ [0.5, 2.0]。任一不过即判"位姿不合理"拒绝——宁可少对齐一张,也不把图贴到九霄云外。

细节⑤ H 的方向:只用来"誊地图",谁都不搬照片

单应 H 映射"基准坐标 → 照片坐标",方向只有一个用途:把基准图上的分区蒙版正向投射到每张照片上(二值蒙版逐点搬家、最近邻插值,不产生灰边),得到那份与照片同样歪斜的"有效检测区"。照片像素与标注多边形永远待在原地——训练切块、贴图、考试推理全部直接在原图坐标系进行,没有任何"搬运标注"的环节(老版要在"掰正后的副本图"上考试、把标注誊来誊去,新版已彻底删除,少了一整套易错的方向口径)。

💡 大白话:一张"查址对照表"

H 就像一张「标准地址 → 现场地址」的对照表:想知道标准地图上的某块地盘出现在某张照片的哪个位置,顺着查就行。照片不搬、标注不搬——要动的只有那张几 KB 的分区蒙版;搬便宜的,不搬贵的。

细节⑤附图一 · 蒙版的正向投射(H):把"地盘"誊到照片上用

分区蒙版画在基准图(基准坐标系)上,而缺陷标注画在每张歪的照片上——两个坐标系不同,没法直接求交。做法:把基准图上的各检测区蒙版按 H 正向投射(二值蒙版逐点搬家、最近邻插值,不产生灰边),再经 ±10px 边缘吸附,得到与照片同样歪斜的"有效检测区",直接覆在照片上用;结果以压缩蒙版(zb64 RLE)存进 align.json 台账,分区 json 原件不动。

🎯 为什么投射蒙版,而不是把标注搬去基准系比?

因为抠真实小图必须落在原图原生像素上做——照片一旦被重采样到基准系,缺陷边缘就糊了;工作现场只能在照片坐标系里。而蒙版是二值图(只有"是/否"),投射它没有任何画质损失。要搬就搬便宜的那方:让几 KB 的蒙版飞到照片那边去,而不是让几十 MB 的照片像素飞过来。如今这套"逆向"思想贯穿到底:连考试推理也直接在 val 原图上做——模型答卷、老师答案、考场范围全在同一个坐标系,谁都不用搬。

💡 大白话:考试为什么连"换算"都省了?

老版要把照片"摆正"后再考试:老师画的圈和模型圈的圈分属两个坐标系,得拿着换算表誊来誊去,方向搞反全盘皆错。新版直接在 val 原图上考试——模型看到的是原片、老师画的是原片、考场范围(圆滑有效检测区)也誊到了原片上,三方同一个坐标系,拿过来就能比。

像全班合影"对表":以班长(基准图)为标准,每个人原地不动,把班长的"名牌位置表"(分区)按每个人的站姿誊一份发到手里。对表只看工装上的花纹(domain 分区内的角点)——别拿背景里的路灯对,那不准。对不上的(对齐失败),练习册和考卷里都除名。

6.4 对齐失败隔离

对齐失败的图不再只是"剔除出名单"——而是成对移出隔离:本轮全部图(点位根目录训练图 + val/ 考卷)先整体对齐一遍收集失败项,再把根目录失败图移入 .tmp/{产品}/align_failed/{点位}/、val/ 下的考卷移入对应隔离位置,并逐条追加记录 moved.jsonl。被隔离的图本轮训练与考试都不再消费;数据修好后下次启动全部重算,自动"归队"。(--reuse 复用产品里配准失败的 NG 图只跳过,复用产品的素材永不移动。)

💡 大白话:请出考场、登记在册

对不上号的照片当场请出考场并登记(移到隔离区 + 记台账)——不带病上场,也不悄悄失踪;下次修好照片(或调好对齐参数)重新开考,它自己会回来。

第 7 章

小图池、专属 LoRA 与统一预算

对应 README 宏观大流程 2~4(阶段1 LoRA / 阶段2 小图池 / 统一预算)+ lora_synth.py / budget.py 源码
💡 大白话:三种卷子

练习册(训练底图造的题)——天天刷,题是现场贴出来的合成缺陷;模拟卷(早停集)——固定一批题每晚考一次,成绩只用来判断"还要不要继续练"(早停);封存的期末卷(val/ 独立考卷)——真缺陷、模型从未见过,只有它说了算谁能"毕业"当 best。三卷各司其职,谁也不能替谁。

7.1 统一注水预算:一份账本管出题与合成(budget.py)

  • 先数家底:预切统计每个背景域 (点位 p, 检测区 z) 的干净块数 T(跳过含标注块)与绑定缺陷种数 D——这是全部配额的出发点;
  • 总预算:单轮正样本总数 B = clip(round(v_base × T 总), Σ下界, min(16000, Σ上界)),其中 v_base = clip(200 ÷ 底图总数, 1, 5);
  • 注水分配:按权重 W = √(T×D) 把 B 分给各区——介于"按面积摊(大区淹没小区)"与"完全均摊(小区过拟合)"之间的折中;下界保底 max(100×D, T÷轮数)(极小/稀有区每种缺陷每轮至少 100 块),上界封顶 5×T(单块单轮最多重复 5 次);
  • 分片轮转:某区 T 超过其配额 E 时自动拆 num_shards = ⌈T÷E⌉(≤轮数)个分片跨轮轮转,保证最大轮数内 100% 底图块参训;轮转完毕前早停不生效;
  • 早停集封顶:每点位 ≤10 张之外,全产品验证干净块全局封顶 1200(= 2400 个正负验证样本),防 100+ 点位验证超时;
  • 切块完整性补块:常规重叠网格之外,自动检查每个分区的每个连通域——外接框装得下却没有网格块完整包含它时,补一个居中块(同样须不含标注)。
💡 大白话:给大小区"注水"分教材

把单轮训练量想象成一桶水,按 √(地盘×题种) 的比例往每个"杯子"(背景域)里倒:大区杯子大就多倒,小区杯子小就少倒——但每只杯子都有保底线(每种题至少 100 块)和封顶线(单块最多重复 5 次),谁也不会饿死、谁也不会撑死。地盘大到一轮喝不完的,自动排队分片、跨轮轮着喝,一轮都不落下。

为什么要这么分?(四连问)

🎯 ① val/ 考卷为什么必须独立?

考试选型(best)面对的必须是模型从未见过的真实缺陷图。考卷单独放在 {点位}/val/ 目录、由人工手工放入,从目录层面就与训练池物理隔离——想漏题都难;训练侧任何扫描都跳过它。

🎯 ② NG 图还能进训练池吗?

能,但角色变了:NG 图负责贡献缺陷实例(抠真实小图、训 LoRA、实测规格);它的图像部分不再被修补利用——凡沾到标注(含外扩 4px)的 512 切块整块跳过,宁缺毋滥。比"修补后再用"更稳:任何修补都是"猜"出来的纹理,猜错了就是假课本;跳过脏块,留下的每一块都是 100% 真实无瑕的相机像素。

🎯 ③ 为什么"跳过"而不是"修补后接着用"?

老版把真缺陷 inpaint 抹平后继续当干净背景用,还要给抹平区标 255 忽略——修补是"猜"纹理,猜错就教假课,忽略区还白白浪费一块地皮。新版直接跳过含标注的块:零猜测、零风险。某个小检测区若因此一块干净块都不剩,系统开局就红字提示"补 15~20 张该区的 OK 底图"(8:2 划分把某区唯一干净图分进早停集时,还会自动把它换回训练池)。

🎯 ④ 训练集切块为什么要随机抖动?

切块位置在网格上随机偏移 ±192px(=步长 384 的一半),防止零件的孔位、边角永远出现在同一坐标被死记硬背。抖动带约束:6 次尝试内必须既避开一切标注(含 4px 外扩)、又保证检测区并集在块内不少于 16px,不行就退回原网格坐标。早停集/考卷不抖——题目固定,分数才可比。

7.2 真实小缺陷图:圆滑区归属 + 原图零失真抠取

逆向对齐完成后,程序立刻干一件老版要人工干几天的事——把每个真缺陷从原图上抠成素材(align.py),对每个非「排除」标注多边形走五步:

  1. 定归属(用圆滑区):缺陷多边形与各圆滑有效检测区求交集——交集面积最大的区赢得这个缺陷(贴边缺陷不会因训练态的向内吸附而被误判出区/误入邻区);按 {检测区}/{缺陷} 归档,同名区跨点位、跨 --reuse 合并;
  2. 完整保留轮廓:掩码就用整条人工标注多边形——贴边缺陷画出界的部分不裁掉(沿检测区边界裁切会把肉眼一体的缺陷"腰斩");
  3. 掩码外中值去背景:优先取小图局部「有效检测区 ∩ 掩码外 ∩ 无标注」像素的灰度中值,把掩码外的一切像素(外扩边距、邻近其他缺陷/「排除」区、区外背景)统一填平(环带内没货则退回整区中值)——每张小图严格只含 1 个缺陷,旋转贴图时边缘带出的是纯平背景而非异色纹理;
  4. 零失真抠取:直接在原始 .bmp 上按标注外框 + 8px 边距抠图,存 patches/{检测区}/{缺陷}/real_*.png;
  5. 实测规格:顺带量出每个实例的面积、对比度(外扩 2~7px 干净环带 |缺陷−背景| 的 p80,环带避开邻近标注)与明暗极性——汇成第 2 章讲的 auto_zones 规格单。
💡 大白话:剪标本,瓶里只留这一件

真实小图像"从现场照片上剪标本":照片本身一张不动,标本按老师画的整圈轮廓剪——圈到检测区边界外也不截断;标本瓶(8px 边距的小图)里凡是圈外的杂物(邻缺陷、反光区、区外背景)一律铺成同一层"干净底色"(有效检测区的背景中值)——瓶里这件标本百分百纯净,拿去量尺寸、当教材、当 LoRA 的形变模板都不会量错、带脏。

💡 大白话:停哪儿有讲究(距离变换智能放置)

💡 大白话:按编号复刻的菜谱

"确定性再生"像按编号出菜的中央厨房:第 1024 号菜的所有随机调料配方(种子)是写死的——今天做和明天做,端出来的缺陷一模一样;每天变的只是上菜顺序。好处:几千道题不用存硬盘(现点现做),而且排查问题时有据可查——同一道题任何时候重做,结果可对照。

8.2 八步流水线总览

对比度定向合成(第④⑥步的一部分):先按该组合的实测对比度 [diff_lo, diff_med, diff_hi] 中位锚定抽一个目标幅度;素材保持原生极性与内部明暗结构(实测极性为"偏暗"的绝不画成亮斑——泊松残差按 polarity 定向、必要时整体反号);残差幅度按标签区 p50+p75 各半的实测幅度定向缩放到目标(限幅 0.5~6.0 倍);最后过一道深孔门控——目标位置越暗,正向(提亮)残差被压得越狠,杜绝在深色背景上画出突兀亮斑。这套参数不存盘、不预处理——全部由实测 auto_zones 而来,新加缺陷照片后下次重跑自动刷新。

💡 大白话:掩码的"半份身份"(m_float)

🎯 为什么抹平?为什么垫边?

抹平:素材外圈带的是别的图的背景纹理,不抹掉会以假梯度混进泊松过渡带;抹平后素材只保留纯正的「缺陷—背景色差」。垫边:贴边缺陷在 0~360° 旋转时,边缘复制填充(BORDER_REPLICATE)会把贴边像素拉成直角三角伪影——垫 1px 背景后,拉长的是背景色,缺陷本体无恙。

8.5 第⑥步:泊松贴图的两件法宝

法宝一:带上下文的画布。贴缺陷不是贴在孤零零的 512 块里,而是先从整图裁出「512 块 + 四周各多裁一圈真实底图」的大画布,把完整素材泊松贴上去,再裁回 512 块——缺陷可以横跨块边(推理时缺陷同样会被块边切开),也不会因为素材被块边截断而融合发虚。越出整图的部分用镜像补齐。

⚠️ 为什么不用 MIXED_CLONE?

源码注明:OpenCV MIXED_CLONE 的源码判据是 |gx − gy|(45° 方向梯度相消),斜向划痕会融合发淡;所以坚持 NORMAL_CLONE + 自己外扩 + 自己柔边回写——斜向划痕的外接框亮三角伪影和砂眼对比度衰减一并根除。

💡 大白话:泊松融合 = 请了位调光师

直接把缺陷"贴"上去像贴贴纸——边缘亮度对不上,一眼假。泊松融合是请了位调光师:保留缺陷的明暗笔触(残差),重新上色时让光线服从底图的环境光——缺陷就像在这块金属上自然长出来的。外扩 5~7px 是给调光师留的工作台(台面上区外先铺区内中值的"桌布",只是防黑边污染求解,不是成品);干完活按"外扩域边缘渐隐"调好笔锋,但落笔严格限制在检测区之内——区外的刀纹分毫不动,相邻槽与背景也绝不沾光。

8.6 第⑦步:落地复检与可见性

  • 严格区内落笔:贴边的"区边缘样本"越出目标区的部分按区截断标签;写回像素严格限制在「缺陷标签 ∩ 有效检测区」内——label=0 的正常背景一个像素都不改,更不会染进相邻检测区;只有越出到所有区并集之外的部分才按 30/40/30 做自然融合过渡。
  • 入区复检(两道关):① 区内正样本 ≥8px;② 按落点分档控入区比例——区边缘落位允许跨界,只需 ≥15% 面积在区内(正是"贴边缺陷"样本);区内落位则要求 ≥70% 在区内。
  • 可见性复检(VISIBLE_MIN_DIFF=8.0):标签区内 |贴后 − 贴前| 的平均灰度差 ≥8,或 75 分位对比度 ≥12(8×1.5),任一达标即通过;两者都不足 → 作废重抽。看不见的缺陷硬标 1 = 噪声标签,会毒化模型("透明正样本")。

第 9 章

模型与训练:一位"带眼力底子"的新学员

对应 README 宏观大流程 4 + seg.py / trainer.py 源码

进入本章前,先把两个最底层的问题掰开:模型是什么?训练在干什么?

模型 = 一台"亿万旋钮的答题机器":吃进一个 512×512 图块(灰度复制成 3 通道),经过几十层加工,吐出一张同尺寸的热力图——每个像素一个 0~1 的分数,越亮越像缺陷。它体内没有"缺陷长这样"的图片库,只有几十亿个数字旋钮;旋钮拧在哪个位置,决定了它现在怎么答题。

训练 = 做题 → 批卷 → 找错 → 拧旋钮,循环几千步:每一步拿一批图块(一半纯净、一半贴了缺陷)让它答题;拿 GT 标签批卷,算出"损失"(一个数字,错得越离谱分越高);反向传播算出"每个旋钮往哪边拧能降分";优化器把每个旋钮只拧一小格(步幅 = 学习率),EMA 顺手记一份近期平均。如此循环,旋钮越来越会答缺陷题。

💡 大白话:刷题备考

前向=答题,损失=扣分,反向传播=对答案、标出每道错题该改哪里,优化器=每次只改一点点(一次大改会崩,学习率就是步幅),EMA=看"平时成绩单"的趋势而不是单次波动;刷完一整本题库 = 1 个 epoch;模考(验证)不再进步就提前收工 = 早停。

9.2 损失:两把尺子一起量,全像素一把到底

损失 = Sigmoid Focal + 3.0 × Dice。Focal(α=0.4, γ=2.0)专治"缺陷像素太少"引起的摆烂——两招:α 让少数派(缺陷像素)的错加倍扣,γ 让已学会的简单题扣分打折(错题相对更显眼),模型因此不敢全答"正常";Dice 则盯整团形状的重合度(且只统计含缺陷的块——纯净块的 dice 被 has_pos 掩码置零,不再混入平均)。训练与验证用同一把全像素稠密尺(loss_utils.py·dense_masked_sums):逐像素全算、自动屏蔽 255 忽略区,训练 loss 与 val_loss 口径完全同构——早期版本训练用 PointRend 抽点采样省算力,但两把尺跨轮不可比、还多一份 vendor 代码,新版统一退役(见词表"PointRend?已退役")。

💡 大白话:一把尺子量到底

早期训练为省算力玩过"聪明批卷"(PointRend 专挑模型最不确定的位置抽点批),验证却用全像素——两把尺读数对不上,曲线解释起来费劲。新版干脆训练和验证共用同一把全像素稠密尺:显卡算力足够,省下的那点算力不值得换来口径分裂;批得全,跨轮成绩才直接可比(见 10.1)。

训练时旋钮每步都在抖,直接拿某一瞬间的值去考试,运气成分大。EMA 另存一份慢速跟随的"近期平均"(0.999)——像长曝光照片,偶发的抖动被时间抹平、趋势清晰;而且验证、考试、交付全用这张长曝光,口径统一。学习率调度则是开车节奏:起步先热车(线性热身约 1 轮,小步试探),巡航后渐渐收油门(余弦回落)——既不熄火也不超速。

10.1 val_loss:固定题集,固定尺子

💡 大白话:铺地砖,留咬合缝

像铺地砖故意让相邻两块砖的边缘咬合 128px:咬合处两块砖的颜色按"你退我进"渐变过渡,远看严丝合缝;而且每块砖的边缘(切割最毛糙的地方)自动被压暗——被采信的主要是每块砖的"肚腹"部分。所以整张热力图上找不到砖缝,也没有块边的突兀深浅。

考试环节用到的具体技术(想深究再看,核心机制上图已讲清):

  • 权重窗公式(blend_window):窗重 w = min(i/ramp, (ts−i)/ramp) 双向取小(ramp = 重叠带 128px),中心 1.0、块边趋 0;相邻两块在重叠带内权重此消彼长、和恒为 1(线性交叉淡入)——热力图在块缝处连续无缝;
  • 全程 GPU:整幅 1200 万像素图以 uint8 一次上显存(约 12MB),切块、归一化、推理、加权缝合、检测区清零全在显存完成,主机侧只一次上传一次取回;
  • 推理细节:bf16 自动混合精度 + sigmoid 概率化;输出尺寸与输入不齐时双线性插值兜底;考卷图/标注多边形/圆滑有效检测区开局预解码缓存,标注直接在原图栅格化后与报警求交集(无任何坐标搬运);
  • 考前内存探针:垃圾回收 + 归还系统堆 + 清空显存缓存,并记录分配重试/OOM 计数——久训后考试变慢,先看这里;
  • 工程坑规避:多卡广播早停分数不走 torch 2.5.1 的 broadcast_object_list(NCCL 下有 bug),标量改用张量直传。
💡 大白话:圈红圈对答案

先说"报警"怎么来:热力图上每个像素各有一个 0~1 的分数,拿这个分数逐像素去和固定的判卷线 0.5 比——过线的像素被点亮(如 0.9 ✓、0.6 ✓、0.3 ✗),连成片就是模型圈的红圈;不是图和图比,是每个像素的分数自己比。然后考试像批"圈红圈"的答卷:模型在考卷上圈红圈(报警像素),老师手里有标准答案(人工标注);综合质量分 = 命中数×1000 + 红圈与答案重合的面积 − 标注外误报面积×0.1——报得准、报得全拿高分,报多了轻微倒扣(防"全场乱报刷检出"),报漏了丢大分(一个缺陷值 1000)。前面那道"加权窗拼接"工序,就是为了红圈在图块接缝处不出现深浅突变。

🎯 阈值 0.5 为什么写死、不扫描调参?

交集随阈值单调变化——扫描选阈值必然滑向最低档(全不报警交集恒 0,或全报警虚高),毫无意义。固定 0.5,把"学得好不好"和"报多严"解耦:前者由训练负责,后者交付时一目了然(manifest 里 threshold 固定 0.5)。

10.4 存档与 best 选型

  • 逐轮存档:总交集 > 0 的轮,EMA 权重 + score.txt 存 .tmp/ep{轮}/(监控页柱状图数据源);每轮无论分数都覆盖一份 .tmp/latest/;
  • 唯一 best(综合质量分选型):quality_score = 命中数 hit_defects × 3000 + 总交集像素 − 0.05 × 标注外误报像素——检出 1 个缺陷 +3000、交集 1 像素 +1、误报 20 像素 −1,优先保召回、兼顾定位与抑制误报;综合分创新高才写 models/(同分依次比检出数、总交集),新超旧删旧——models/ 里永远只有一个 best_int{交集}_ep{轮}.pth,元数据同时记录命中数与综合分;
  • 全程总交集恒为 0 → 不产 best,大声告警提示人工排查(逐轮权重还在 .tmp/ep*/ 里,可指定 --base 再练)。
💡 什么算"考过"?—— 刷纪录的赛马制

考试没有绝对及格线,只跟自己的历史最高比,四种结局:

  • ✅ 创纪录:综合质量分(命中数×3000 + 总交集 − 0.05×误报)超历史最高 → 本轮 EMA 权重当上 best,写入 models/ 并刷新 deploy 包(唯一被"考过"的情形);
  • 😐 会画但没破纪录:分数 > 0 却不超历史最高 → 存档 .tmp/ep{轮}/,不交付;
  • ❌ 一分没捞着:总交集 = 0 → 本轮不进 best;全程恒为 0 → 不产 best、models/ 为空,告警人工排查;
  • ⚠️ 考卷作废:单图超 10 秒(模型病态)或考试异常 → 当轮成绩作废,训练照常继续。

"没考过"≠重来:训练不因考砸中断,一直练到早停或轮数上限,考试只决定 best 的归属。误报为什么只轻罚(20 像素扣 1 分)?标注不全时报警里可能混着没被标注的真缺陷——重罚会逼模型学会漏报;但完全不罚又防不住"全场乱报刷检出数"的碰巧模型,0.05 的系数正好两全。

12.2 多卡并行(检测到几张显卡自动几张)

  • 各卡 DDP 并行训练,共享同一注水预算与牌靴(无放回发牌序号跨卡完全一致,每分片内严格正负 1:1,超大区跨轮分片轮转);
  • 考试由 0 号卡独占执行,其余卡等待(避免重复计算,看门狗放宽到 60 分钟);
  • 阶段 1~2 的 FLUX 训练与合成也吃多卡:LoRA 训练 DDP 并行、重绘任务按卡交错分片,配额补足后立即卸载 FLUX 释放全部显存,再开始分割训练——两段任务不抢显存;
  • 原始底图有 LRU 内存缓存:预算 =(可用内存 − 8G)× 0.6,由全部缓存持有者均分——同一张大图被它切出的几十个块反复读,缓存后每样本省一次 12MP 位图解码(几十毫秒);新版再加父进程预热 + 写时复制(COW)只读共享:预热在父进程完成后,DataLoader 子进程 fork 直接共享物理内存,避免约 1.6GB 图像经进程间管道序列化搬运,worker 内惰性填充;
