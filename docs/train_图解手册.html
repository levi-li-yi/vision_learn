第 0 章

开场白:train 是一座"缺陷驾校"

对应 README 开头「train —— 多点位单模型缺陷分割训练」
📖 先听个故事

上一本《synth_assets 图解手册》讲的是"兵工厂"——量产缺陷素材。素材攒够了,该让"新兵"上场学本领了:教会一个 AI 模型看一眼金属零件照片,就把缺陷的准确位置圈出来(这项活叫"缺陷分割")。这就是 train 仓库的使命。

教学有个老大难:缺陷是稀罕物,真图没几张。train 的妙招是"现场出题":拿现场的干净大图当卷子,随机把合成缺陷贴上去(贴得光影自然,像真长出来的一样),贴哪儿就教模型"哪儿是缺陷"。相当于驾校在自己场地上摆锥桶练车——锥桶想摆多少摆多少。

但光练不行,还得真考:现场拍到的真实缺陷图(NG 图)固定抽出 20% 当独立考卷,整张图从不进训练——模型考得好不好,看的全是它没见过的真缺陷。考得最好的那一轮权重,成为唯一交付的 best 模型,连同推理所需的配置一起打成 deploy/ 推理包。

还有个关键词叫"多点位单模型":一个产品的全部相机机位(点位)不各训各的,而是混在一起训成一个模型——一个产品只交付一个模型文件。

这本手册怎么读?

  • 每章对应 README「训练事件线」的一个阶段,并补充了源码里的真实细节(常量、公式、坑);
  • 看不懂的词随时回第 1 章词表;绿色小方块 512 是关键数字,第 13 章有完整速查表;
  • 四色提示框:💡蓝色=大白话比喻,🎯绿色=为什么这么设计,⚠️黄色=注意/坑,📖紫色=故事;
  • 与《synth_assets 图解手册》是姊妹篇:素材从哪来、泊松贴图的底层细节,那本讲得更细,本册自包含但点到即止。
第 1 章

新手词表:先搞懂这些词,后文畅通无阻

README 与 train 源码里出现的所有"黑话",按主题分组

🖼️ 看图与数据

点位产线上相机机位的编号(如 JXFB-1-P1、JXFB-1-P5),一个点位一个文件夹,内放该机位拍的原图。
基准图 {基准图名}.bmp每个点位选定的"标准照片",配套 {基准图名}.json 分区定义。全点位其他照片都要向它"对齐看齐"。
分区基准图上人工画好的区域(存于 json),如「加工面」= 允许出现缺陷、需要检测的区域。
domain 分区一种特殊分区,名字必须叫 "domain",专供对齐使用——只有这个分区里的图像内容参与位置匹配,夹具、背景、反光都不算数。每个点位必备。
检测区绑了缺陷资产的分区之并集——训练与考试只在这块区域内出题/算分,区外一概不管。
NG 图 / OK 图NG = 带真实缺陷的照片(.tmp 标注里有 label ≠ "排除" 的多边形);OK = 干净照片(无标注,或只标了「排除」)。
.tmp 标注与原图同名的多边形标注文件;label 为「砂眼」「划痕」等 = 真缺陷,「排除」= 刻意忽略的区域(如反光亮斑)。
切块(tile)模型一次只"看" 512×512 的小块;整张大图按网格切成许多块分别推理,再拼回整图。stride(步长)384 = 相邻块错开 128px 重叠。
热力图模型对整图每个像素的"是缺陷"打分(0~1),画成一张温度图——越亮越像缺陷。超过 0.5 就报警。
GT 标签(真值)训练时告诉模型的标准答案图:缺陷 = 1,正常背景 = 0,不用学的地方 = 255(忽略)。
总交集考试分数:所有考卷上「模型报警像素 ∩ 人工标注像素」的总面积。双方都用实际形状,不用外接方框。

🧭 对齐相关

对齐(align)相机每次拍的位置总有毫米级偏差。把每张照片"搬"回基准图坐标系,让同一位置在各张图里像素对像素重合,才能跨图混着训练。
Harris 角点图像里"往哪个方向看都在变"的点(拐角、交界处),是匹配两图位置的锚钉。怎么算出来的、为什么非它不可?见 6.2 开头的三格图解。
RANSAC"少数派报告"式稳健匹配:拿角点配对猜变换,大多数配对都认同的那个才采信,个别错配直接出局。
单应矩阵 H(8 自由度)一张 3×3 的"坐标换算表",能表达平移+旋转+缩放+透视歪斜,把一张图的位置换算到另一张图。
内点(inliers)认同最终变换的角点配对数,少于 6 个判定对齐失败。
有效像素掩码(native)对齐回贴后,标出"这个位置真的拍到了内容"的黑白图——回贴后图外没内容的地方不算数。

🎓 训练相关

模型 / 权重模型 = 会看图的"电子大脑";权重 = 脑内亿万数字旋钮。训练就是反复做题拧旋钮。best_int…_.pth 就是存旋钮的文件。
EfficientViT-SAM L1官方预训练的视觉骨干网络(SA-1B 数据集热启动),train 拿它当"底子"再改造,不从零学起。
骨干 / 冻结骨干 = 模型前端负责"看懂纹理"的大层。冻结 = 这些旋钮锁死不动,保住预训练的通用眼力。
LoRA(分割侧)给冻结的卷积层外挂小旁路(r=16,零初始化起步),只训旁路——小数据微调不伤底子。与 synth_assets 里的 LoRA 同思想、不同对象。
Focal 损失给"稀少的缺陷像素"加权打分的损失函数——缺陷只占画面零头,不加权模型会摆烂全答"正常"。
Dice 损失衡量"圈出来的形状和答案重合度"的损失(1 = 完美重合),和 Focal 加在一起用(权重 ×3)。
PointRend 智能采样训练算损失不逐像素全算,而是抽一批点、其中 75% 专挑模型最拿不准的位置(源自 detectron2)。像老师专批涂改最多的地方——训练专用;验证用全像素,详见 9.2/10.1。
epoch(轮)把训练题集完整过一遍 = 1 轮;上限 20 轮,练满 8 轮后允许早停。
batch一次同时喂给显卡的图块数。不手填——按显存自动算(显存 GB ÷ 3,夹在 8~16)。
学习率 / 热身 / 余弦每步拧旋钮的幅度。先线性热身(1 轮,从小步开始),再按余弦曲线缓缓收小。
val_loss 与早停每轮在固定验证题集上算损失;连 4 轮不降(且已练满 8 轮)就提前收工,防过拟合。
EMA(近期平均权重)另存一份"滑动平均"的权重(decay 0.999)——把近期每步的抖动平均掉,验证/考试/交付全用这份,口径统一。
bf16低精度记数法,省显存提速;指数位与 fp32 相同,不会下溢,无需损失缩放。
DDP 多卡多张显卡分工并行训练,各卡独立造题(种子不同),考试只由 0 号卡独占执行。
迁移 / 精调(--base)不从头学,拿现成权重当起点:官方骨干,或自家/他产品的 best_*.pth。

🧩 图像处理手法

泊松融合(seamlessClone)把缺陷的明暗变化"解方程"融进底图,灯光自然衔接。用 NORMAL_CLONE 模式(MIXED_CLONE 的 45° 梯度判据会让斜划痕发淡,弃用)。
内部腐蚀 4pxOpenCV 泊松底层会偷偷把掩码向内啃 4px——所以送入前必须先外扩 5~7px 保住缺陷边缘梯度。
柔边回写泊松结果不整块照抄:按原掩码 1px 高斯柔化的权重,只把缺陷本体混回底图,掩码外 100% 保留原图刀纹。
对数均匀抽样在 [min, max] 里抽目标大小时"每个数量级等概率"——普通均匀抽样会让大缺陷霸屏,小砂眼几乎抽不到。
上下文画布贴缺陷不止贴在 512 块内,而是贴在「块 + 四周一圈真实底图」的大画布上再裁回——跨块缺陷也能完整融合。
边缘复制填充旋转素材时,空出来的角落用边缘像素复制填满,避免黑角混进内容。
重叠窗加权拼接整图切块推理后,相邻块 128px 重叠带按"此消彼长"的线性权重窗拼回,块边(最不准处)自动降权,热力图无拼缝。

🏗️ 工程协作

uvPython 项目快速运行器,uv run train 一条命令自动配环境再启动。
监控 web(8300)训练时自动开的网页(http://服务器IP:8300),看曲线、NG 图、热力图;无鉴权,仅限内网。
best 权重models/ 里唯一的最终模型文件,文件名自带成绩:best_int1200_ep10.pth = 总交集 1200、第 10 轮。
deploy/ 推理包按点位分子目录的"开箱即用"包:各点位的 json + 基准图 + assets.jsonc + manifest.json 清单。

真缺陷图旁放同名 .bmp.tmp 标注

③ 画分区蒙版用 define_masks 打开基准图画分区

④ 绑定分区与资产手写 assets.jsonc:

assets.jsonc:一张"贴题规格表"

// datasets/{产品}/{点位}/assets.jsonc (人工维护 · 支持 // 注释)
{
  "加工面": [
    {"dir": "../assets/砂眼", "type": "area",   "min": 800, "max": 2500},
    {"dir": "../assets/划痕", "type": "length", "min": 60,  "max": 150}
  ]
}
// type: "area" = 掩码像素面积 | "length" = 外接框长边
// min / max: 贴入后的落地像素范围 (训练时自动缩放素材匹配该范围)
💡 大白话

这张表就是"出题规格单":加工面上只准贴两类题——砂眼(按面积算,贴完要落在 800~2500 像素)和划痕(按长度算,落地 60~150 像素)。素材原本多大无所谓,训练时会自动缩放到位、贴完再复检。一个分区绑多个目录 = 混着贴。

⚠️ 两个易错点

① 素材必须是单通道灰度 PNG,且靠"同名 + _mask.png"自动配对——不需要也不支持 manifest.csv,预览图(preview_*.png)、txt 等无配对文件天然被跳过;② 判一张图是不是 NG(带缺陷),看的是 .tmp 里有没有 label ≠ "排除" 的多边形——只标了「排除」的图算 OK 干净图。

💡 大白话:开驾校前的备料

四件事对应驾校四样家当:教练车(缺陷素材,一车一驾照图 = png+mask 配对)、训练场地(现场原图)、场地围栏(分区,圈出哪块能练)、课程表(assets.jsonc,哪种场地摆哪种桩、摆多大)。缺一样,驾校开不了张——体检(第 5 章)会逐样点数。

💡 大白话:档案柜与草稿纸

models/ 是只放成品的档案柜——而且永远只留一件最好的(best),换新的删旧的;.tmp/ 是草稿纸篓——对齐缓存、逐轮权重、日志随手扔,整篓倒掉也不心疼(旧篓还会自动归档留 3 篓备查)。正因如此,每次开新会话才敢"清空重来"。

3.2 启动命令与参数

常用命令

$ uv run train # datasets/ 下唯一产品时零参数直接跑 $ uv run train --product HT12 $ uv run train --product HT12 --points JXFB-1-P1,JXFB-1-P5 $ uv run train --product HT12 --base models/HT12/best_int1200_ep10.pth
参数缺省值大白话
--product唯一产品自动选中datasets/ 下多个产品时必须显式指定——程序"绝不猜",会报错列出让你选。
--epochs20本次最大训练轮数;触发早停会提前收工。
--basepretrained/pretrained.pth.tar起步权重:官方骨干,或指向任意 best_*.pth 做迁移精调(自家或他产品都行)。
--points全部点位只训指定点位,逗号分隔。
--monitor_only关只开监控网页不拉训练(不清空 models/ 与 .tmp,历史全保留)。

3.3 autotune:训练三参数不用人填

🧮 自动解算公式(源码)

  • batch = 显存 GB ÷ 3,夹在 8~16;
  • 学习率 = 4e-4 × batch/8(LoRA 旁路固定 1e-4 小步);
  • workers = CPU 逻辑核 ÷ 2,夹在 2~8。

💡 大白话

换台显存更大的机器,自动多吃多练;小机器自动细嚼慢咽——同一台机器上重算结果一致,所以重启也不需要记录这些参数。

第 4 章

训练事件线总览:一条命令的旅程

对应 README §三「训练事件线(全景树)」

敲下 uv run train,程序自动走完五段旅程:

0. 素材体检 checkup.py

  • 校验分区 json / 基准图 / 资产配对 / 全点位同分辨率 / 标注合法性;
  • 不合格直接退出,绝不代建——错就大声报错,不偷偷帮你补文件。

1. 整图对齐 align.py

  • 用 domain 分区角点解算 8 自由度单应 H;
  • 全部原图回贴到基准图坐标系 → 存 .tmp 对齐缓存(每次启动重算)。

2. 固定分卷 dataset.py·split_roster

  • 带缺陷标注的 NG 图:20% → 独立考卷(整图永不进训练),80% → 借作训练底图(真缺陷区标 255 忽略);
  • 无缺陷 OK 图 + 80% NG 底图 → 训练池,再 8:2 分出训练集 / 验证集(val);
  • 底图名单设上限,富余按拍摄新近度加权抽。

3. Epoch 循环(上限 20 轮;早停:练满 8 轮后 val_loss 连续 4 轮不降)

  • [A 在线切块与合成缺陷]:50% 纯净块 + 50% 贴缺陷块,每块 5 个变体(细节在第 8 章);

第 6 章

事件线 1 · 整图对齐:把所有照片搬回同一坐标系

对应 README 事件线 1 + align.py 源码

6.1 为什么必须对齐?

相机每次拍照,工件位置总有毫米级偏差(挪了一点、歪了一点)。不对齐的话,"加工面左上角"在不同照片里对应的像素各不相同,混着训练就全乱了。对齐 = 求一个变换,把每张照片都搬回基准图的坐标系,让同一位置像素对像素重合。

6.2 怎么对齐:角点配对 + 稳健解算

讲配对之前,先把地基打好——角点 = 画面里"往哪个方向看都在变"的点,也就是各种拐角、交界的位置。Harris 检测的思路很直白:拿一个小窗口框在每个像素上,问一句"把窗口往任意方向挪一点,里面的内容变不变?"——两个方向都变的,就是角点。

💡 大白话:认人靠痣,不靠"有皮肤"

平坦区像一面空墙,没有任何记号;边缘像一条长长的线,线上每个点长得一模一样,挪一挪就认不出谁是谁;角点像墙角的插座、脸上的痣——独一无二,一眼锁定。基准图和待测图要认出"同一个点"来配对,靠的正是角点这种"胎记":配出几十对,才能解出单应 H 那张坐标换算表。金属表面看着平,放大全是刀纹、螺纹、微坑,微观拐角遍地——所以角点管够,还嫌多(所以才要 6.3 的"每格取最强 30 个"限额)。

地基打好,回到正题。对齐器与 define_masks 的对齐实验完全同款(Point8DofAligner,全程 Halcon 原生算子)。具体用到的技术依次是:points_harris 找角点(只在 domain 分区内)→ 分 6×6 格、每格取最强 30 个 → proj_match_points_ransac 稳健配对解单应(NCC 灰度匹配、匹配掩窗 10px、gold_standard 精解、内点距离阈 1.5px、搜索容差 80px、随机种子 42 固定可复现)→ projective_trans_image 双线性回贴;内点不足 6 个直接判失败。

💡 大白话:单应矩阵 = 一张"透明胶片摆放说明书"

想象把待测图印在一张透明胶片上,要摆到基准图上严丝合缝——可以平移、旋转、均匀放大缩小,还能透视歪斜(近大远小那种斜)。这几类动作合起来正好 8 个自由度;单应矩阵 H 就是那张 3×3 的"摆放说明书":给它一个基准图坐标,它告诉你该去待测图哪个位置取样。

💡 大白话:RANSAC = 少数派报告出局

角点配对里难免混进错配——两处长得很像的刀纹认错了人。RANSAC 的玩法像投票听证:随机抽几对配对试算一个变换,然后让全体配对投票——按这个变换换算后仍对得上的算"认同票";反复试、取认同票最多(内点最多)的变换当选,投反对票的错配直接出局。所以个别认错人,带不偏最终结果。

💡 大白话:有效像素掩码 = "真拍到"印章

回贴像把拍歪的照片掰正——掰正后,画布的某些角落其实是空的(原图根本没拍到那里)。有效像素掩码就是在掰正结果上盖个章:"这些位置是实拍的"。后续训练、考试只认盖过章的像素,空角落一概不算数。

6.3 源码里的工程细节(逐条图解)

先给五条细节记一句口诀:快、匀、稳、省、准——每条解决对齐环节里的一个具体毛病:

细节作用(一个字)大白话没有它会怎样
① 结构尺度快 + 准粗活(找点、配对、解单应)在缩小图上干,又快又稳;真正"搬像素"时换回原图,清晰度一点不丢对齐一张图要很久,还容易错配
② 分网格均匀采样匀角点天然扎堆在花纹多的地方;每格限额后格格有锚钉,解出的变换对整幅图负责变换只迁就扎堆的一小块,远处区域全贴歪
③ 合理性检查稳给解出的变换当"安检门"——跑飞的(位移过大/缩放离谱)直接拒绝错配点把解算带偏,照片被贴到九霄云外,悄悄毒化数据
④ 对齐缓存省对齐耗时但本轮结果唯一——算一次存档,后面造题、考试直接读;下次启动删了重来每次切块、每场考试都重新对齐,白白浪费大量时间
⑤ H 方向口径准一张"查址表"定死两个方向:回贴顺着查、搬标注逆着查,全工程统一方向用反,图和标注一搬就歪,考试计分全错还难排查
💡 大白话:一条流水线的五道工序

把五条串起来看,就是给"把几百张现场照片摆进同一张标准地图"这条流水线装的五道工序:先用小图快速找到锚钉(快),再把锚钉铺满全图(匀),解出的变换过一遍安检(稳),结果存档反复用(省),最后所有搬运统一方向(准)。少了任何一道,照片要么摆得慢、要么摆得歪、要么搬丢了。

细节① 结构尺度:找点用小图,搬家用大图

直接在几千像素的大图上找角点、配对,又慢又容易错配。做法是先等比缩到宽 512(结构尺度)把"找点 + 配对 + 解单应"全干完,再把解出的单应换算回全分辨率、用原图回贴——锐度一点不丢。搜索容差默认 80px:每个基准角点只在邻域 ±80px(按尺度折算)内找待测伙伴;待测图偏移大时可在 json 的 align 段加大。

细节② 分网格均匀采样:36 格 × 每格 30 个,全图都有锚钉

Harris 角点天然"扎堆"——亮纹理、花纹多的地方一口气冒出几百个,平整区域一个没有。把图分成 6×6 格、每格只取响应最强的 30 个,保证每个角落都有锚钉,解算的单应才对全图负责。

细节③ 合理性检查:防"匹配跑飞"

解出的单应先过两道体检:四角最大位移 ≤ 图边长的 15%、缩放行列式 det ∈ [0.5, 2.0]。任一不过即判"位姿不合理"拒绝——宁可少对齐一张,也不把图贴到九霄云外。

细节⑤ H 的方向口径:正向取样,反向搬标注

单应 H 映射"基准坐标 → 待测坐标"。于是有两趟方向相反的旅程:回贴时,对齐图(基准系)的每个位置 p,顺着 H 去待测图取 H(p) 处的像素;而标注多边形画在待测图(原图)上,考试要和基准系的预测对齐算分,搬回基准系必须逆着走 H⁻¹。

💡 大白话:一张"查址对照表"

H 就像一张「标准地址 → 现场地址」的对照表。把现场照片搬回标准地图,是顺着查:标准地图上每个位置,按表去现场取对应像素填进来;把现场图上画的圈(标注)搬回标准地图,是逆着查:现场地址反查标准地址。表只有一张,方向别搞反——反了就把图搬歪了。

💡 大白话

第 7 章

事件线 2 · 固定分卷:练习册、模拟卷与封存的考卷

对应 README 事件线 2 + dataset.py·split_roster 源码 + §四.1「分卷与底图防误导机制」
💡 大白话:三种卷子

练习册(训练集)——天天刷,题是现场贴出来的合成缺陷;模拟卷(val)——固定一批题每晚考一次,成绩只用来判断"还要不要继续练"(早停);封存的期末卷(独立考卷)——真缺陷、模型从未见过,只有它说了算谁能"毕业"当 best。三卷各司其职,谁也不能替谁。

7.1 分卷的三个技术细节(源码)

  • 怎么知道照片新旧:文件名内嵌毫秒时间戳优先(如 P6_1789887619474.bmp),没有时间戳的(如 View_14_1085.bmp)退回文件修改时间——批量拷贝会把修改时间拉平,只能算近似;
  • 新近度加权公式:照片按新到旧排序后,第 i 张的抽中权重 w = 0.5^(i ÷ (n/4))——库存 n 张里,每往后排"四分之一",权重减半;
  • 名单量 target = min(500, 各点位最多张数, 最少张数 × 4):不让素材多的点位把题量差距拉得太悬殊;不足则循环补齐。
💡 大白话:新照片插队

抽底图像"排队报名"——最新的照片最可能代表产线的当前状态(刀具磨损到哪了、光照怎么微调的,都是最新的最准),所以给它插队优先;老照片也有机会,只是越旧概率越低(每往后排四分之一就减半)。固定种子下,这套抽签结果完全可复现。

为什么要这么分?(四连问)

🎯 ① 20% 考卷为什么必须独立?

考试选型(best)面对的必须是模型从未见过的真实缺陷图。考卷图哪怕借一个角当训练底图,都算漏题——所以整图封存,一个像素都不进训练。

🎯 ② 80% NG 图为什么敢借来当底图?

现场采集的图很宝贵。借的是 NG 图上大片无缺陷的正常表面来贴合成缺陷;图上原有的真缺陷区标 255(忽略)——算 Loss 时直接跳过,不教也不罚,不会误导模型;合成缺陷落点也自动避开这些区域。

🎯 ③ 底图真缺陷为什么要外扩 4px 再标 255?

人工画框往往紧贴缺陷内侧,外圈 2~4px 其实是缺陷的过渡边。不外扩的话,这段过渡会被当成"正常背景 0"教给模型,模型就不敢报真缺陷的边缘。外扩 4px(源码常量 ANN_DILATE=4)把过渡带一并屏蔽。

🎯 ④ 训练集切块为什么要随机抖动?

切块位置在网格上随机偏移 ±stride/2(±192px)。不抖的话,工件的孔位、边角永远出现在图块同一坐标,模型会死记硬背位置而不是学看缺陷。验证集不抖——题目固定,分数才可比。

第 8 章

事件线 3A · 在线造题:贴缺陷的八步流水线

对应 README 事件线 3[A] + dataset.py/_paste 源码 + §四.2「缺陷合成与泊松融合机制」

8.1 造多少题?—— 固定缺陷池,按种子"确定性再生"

每个 epoch 的题量 = 切块数 × 2(一半纯净、一半贴缺陷)× 每块 5 个变体。所有块和缺陷不落盘:每个样本的缺陷由定死的种子确定性再生——同一下标每次合成出完全相同的缺陷,等效于一个固定题池但不占磁盘;每轮变化的只有刷题顺序和读取时的随机增强。

抽素材的规则(assets.py):先等概率选一个绑定目录、再等概率选其中一张素材(一个分区绑多目录 = 混着贴);全部素材在启动时一次性预处理并常驻内存(读入时掩码按 >127 二值化、去背景、垫边,之后反复取用,不再碰磁盘——LRU 不淘汰,因为预处理只做这一次)。贴到哪个分区:块内与各分区有效像素交集超过 100px 的分区中随机挑一个,贴 1 个缺陷;落点再避开底图已有的真实缺陷标注区。

💡 大白话:抽奖箱 + 食堂备菜

抽奖箱:assets.jsonc 里"加工面"绑了砂眼、划痕两个目录,就是两个抽奖箱——先等概率挑箱子,再在箱里等概率抽一张。箱子层面公平:哪怕砂眼只有 10 张、划痕有 90 张,两类被贴出的机会仍各占一半(想改比例,改绑定即可)。食堂备菜:开工前把所有菜洗好、切好、装盘(启动时一次性预处理),出餐时直接抓——不为每一张订单现跑一趟菜场(重新读盘+处理)。

💡 大白话:倒车入位

往分区里贴缺陷像倒车入位:停车场有很多车位(各分区),先看哪些车位够大(与本块交集 > 100px 才算真车位);随机挑一个够大的;再在车位里绕开障碍物(底图真缺陷标注)随机选个位置停进去(落锚点、贴 1 个缺陷)。蹭到边的不算车位,压障碍物的位置不选。

💡 大白话:按编号复刻的菜谱

"确定性再生"像按编号出菜的中央厨房:第 1024 号菜的所有随机调料配方(种子)是写死的——今天做和明天做,端出来的缺陷一模一样;每天变的只是上菜顺序。好处:几千道题不用存硬盘(现点现做),而且排查问题时有据可查——同一道题任何时候重做,结果可对照。

8.2 八步流水线总览

💡 大白话:掩码的"半份身份"(m_float)

素材一旋转,缺陷边缘的像素就有的半进半出。掩码不搞四舍五入,而是给每个像素记一个 0~1 的连续"覆盖度"——之后 0.4 以上的当"克隆用掩码"(送泊松)、0.25 以上的算"缺陷标签"(边缘低阈值连通)。一份浮点掩码,两道门槛各取所需。

8.3 第②步:内存去背景与贴边垫 1px(assets.py)

素材小图读进内存时(磁盘原文件不动):掩码外(~mask)全部抹平为自身灰度中位数;若掩码贴着图边,自动向外垫 1px 背景色。

🎯 为什么抹平?为什么垫边?

抹平:素材外圈带的是别的图的背景纹理,不抹掉会以假梯度混进泊松过渡带;抹平后素材只保留纯正的「缺陷—背景色差」。垫边:贴边缺陷在 0~360° 旋转时,边缘复制填充(BORDER_REPLICATE)会把贴边像素拉成直角三角伪影——垫 1px 背景后,拉长的是背景色,缺陷本体无恙。

8.4 第③步:对数均匀抽尺寸——小缺陷的公平出场权

8.5 第⑥步:泊松贴图的两件法宝

法宝一:带上下文的画布。贴缺陷不是贴在孤零零的 512 块里,而是先从整图裁出「512 块 + 四周各多裁一圈真实底图」的大画布,把完整素材泊松贴上去,再裁回 512 块——缺陷可以横跨块边(推理时缺陷同样会被块边切开),也不会因为素材被块边截断而融合发虚。越出整图的部分用镜像补齐。

法宝二:外扩求解 + 原掩码柔边回写。这是全流水线最精巧的一段:

关键数字含义
>0.4m_float 覆盖度超 0.4 才算"克隆用掩码"(送去解泊松的那份)
5~7px克隆前掩码外扩量(随机抽),必须盖过 OpenCV 内部腐蚀的 4px
1px 柔边回写权重 = 原掩码 m_float 经高斯(3×3, σ0.8)柔化,缺陷本体软混合、掩码外原样
>0.25GT 标签门限——比克隆用的 0.4 更低,边缘"低阈值连通"都算缺陷
垫边外扩越出素材边界时,复制最边缘像素垫够宽(条件触发,不是每次都垫)
⚠️ 为什么不用 MIXED_CLONE?

源码注明:OpenCV MIXED_CLONE 的源码判据是 |gx − gy|(45° 方向梯度相消),斜向划痕会融合发淡;所以坚持 NORMAL_CLONE + 自己外扩 + 自己柔边回写——斜向划痕的外接框亮三角伪影和砂眼对比度衰减一并根除。

💡 大白话:泊松融合 = 请了位调光师

直接把缺陷"贴"上去像贴贴纸——边缘亮度对不上,一眼假。泊松融合是请了位调光师:保留缺陷的明暗笔触(哪里亮哪里暗的"画法"),但重新上色时让光线服从底图的环境光——缺陷就像在这块金属上自然长出来的。外扩 5~7px 是给调光师留的工作台;干完活只把缺陷本体请进正屋(柔边回写),工作台拆掉、外面原样还原。

8.6 第⑦步:截断与两道复检

  • 截断到检测区:泊松融合先完整做完,再把超出检测区(如加工面外)的像素还原成原底图——缺陷贴在加工面边缘时呈现自然的「到边界戛然而止」,不会在区域边缘留一圈假融合接缝;标签也夹回区内。
  • 落地规格复检:量截断后的区内真值,面积/长度必须仍在 [min, max] 内——超了就重抽。
  • 可见性复检(VISIBLE_MIN_DIFF):标签区内 |贴后 − 贴前| 的平均灰度差不足 4.0 灰度级 → 作废重抽。看不见的缺陷硬标 1 = 噪声标签,会毒化模型("透明正样本")。
💡 大白话:缺陷长到墙边就"戛然而止"

贴在加工面边缘的缺陷,融合完先把探出墙外(检测区外)的部分拆掉、还原成原底图——像藤蔓长到围墙自动打住,而不是翻墙长出去;拆完还要量一量:剩下的够不够规格([min,max])、够不够显眼(灰度差 ≥4)——不够就整题作废重贴。

8.7 第⑧步:GT 标签——一张图三种值

💡 大白话:灰度图为什么要复制成 3 通道?

送进模型前,灰度图要复制 3 份"冒充"彩色照(3 通道),归一化参数也用 ImageNet 那一套——因为骨干网络当年是在海量彩色照片上预训练的,只认 3 通道输入;照着它熟悉的格式喂,预训练的眼力才接得上。

💡 大白话:标签 = 作战地图

GT 标签像发给模型的作战地图,三色分明:白色(1)= 敌人(缺陷),见到就打;灰色(0)= 平民(正常金属),绝对不许碰;黄色(255)= 禁区(检测区外、真缺陷边缘过渡带)——停火,既不奖也不罚,模型不用对这里表态。

第 9 章

事件线 3B · 模型与训练:一位"带眼力底子"的新学员

对应 README 事件线 3[B] + seg.py / trainer.py 源码

9.1 模型长什么样?

起点是官方 EfficientViT-SAM L1 骨干(SA-1B 海量数据预训练,自带"看懂纹理"的底子),然后动三处手术:

LoRA 旁路的技术细节(seg.py):只给 stages 3~4 里"输入输出都 ≥64 通道的 1×1 卷积"挂旁路;挂上后前向变成 conv(x) + (α/r)·B(A(x))(r=16、α=32),A 用 Kaiming 初始化、B 零初始化,旁路还带 Dropout 0.05 防过拟合。分割头则是逐级"反卷积(ConvTranspose2d)×2 + 末段双线性 ×2"把小特征图精密放大回原分辨率。

💡 大白话:新学徒的"影子学法"

B 零初始化 = 新学徒第一天完全照抄老师傅:旁路输出恒为 0,模型行为和原版一模一样(起步恒等),不会一上来就帮倒忙;随训练慢慢加上自己的小修正。反卷积上采样则像"精密放大镜"——把压缩过的小特征图一级级放大到和原图一样大,才能逐像素回答"这里是不是缺陷"。

9.2 损失:两把尺子一起量

损失 = Sigmoid Focal + 3.0 × Dice。Focal(α=0.4, γ=2.0)专治"缺陷像素稀少":错得分越狠、越是少数派,扣分越重,逼模型不敢摆烂全答"正常";Dice 盯整体形状重合度。但训练时不是逐像素全算——走 PointRend 智能采样(源自 detectron2;Windows 装不动 detectron2,就把用到的三个纯函数逐行 vendor 进仓库):每块抽 256×256 个点,其中 75% 专挑"模型当前最拿不准"的位置量(过采样比 3.0)、25% 随机抽查;采样点的双线性邻域必须完整落在检测区内(有效性权重 ≥0.999)才计损失——255 区天然零权重。

💡 大白话:老师批作业不逐字看

PointRend 批起作业来不像逐字批改的老师,更像一位聪明的老师:专挑学生涂涂改改(最不确定)的地方细看,再随机翻几页防漏——省时间又打在痛处。为什么训练敢"挑着量"?因为训练只负责"推着进步",不需要跨轮比大小;验证(val_loss)才特意换成全像素固定尺(见 10.1),两种口径各干各的活。

9.3 优化器:四组旋钮各挂各的档

参数组学习率大白话
LoRA 旁路1e-4小火慢炖:别惊动预训练的底子
骨干后段非 LoRA 可训参数(bb)1e-4
neck(颈部)主 lr(4e-4×batch/8)大火爆炒:新装的部件放开学
head(分割头)主 lr
  • 调度:先线性热身(约 1 轮,从小步起步)再余弦回落缓缓收小;
  • 梯度裁剪(max_norm 1.0)防某一步暴走;bf16 训练省显存,且与 fp32 指数位相同、无需损失缩放;
  • EMA 近期平均权重(decay 0.999):另存一份"滑动平均"旋钮,起步带热身防被随机初值拖死;验证/考试/交付全用这一份——评估口径与落盘口径必须同源,否则日志高分、重载低分;
  • 优化器 AdamW(fused 加速版):动量 β = 0.9/0.999、权重衰减 1e-2;余弦回落的最低学习率 1e-5;多卡训练时 BatchNorm 自动换 SyncBatchNorm(跨卡同步统计量);
  • EMA 细节:衰减系数带热身 d = min(0.999, (1+step)/(10+step))(起步不被随机初值拖死);BN 滑动统计量等浮点缓冲也做同样的滑动平均,整数缓冲直接照抄;
  • 起步权重自动识别(ckpt_utils):权重文件里全是 image_encoder.* 键 → 当"官方骨干"部分载入并严格校验(LoRA/分割头保持新初始化);否则当"全模型"整体载入——所以 --base 指向自家或他产品的 best 都能直接吃;
  • 训练指标(iou 等)全程在 GPU 上累加,每 100 步才取回主机一次——不为打日志拖慢训练。
💡 大白话:EMA = 给旋钮拍"长曝光"

训练时旋钮每步都在抖,直接拿某一瞬间的值去考试,运气成分大。EMA 另存一份慢速跟随的"近期平均"(0.999)——像长曝光照片,偶发的抖动被时间抹平、趋势清晰;而且验证、考试、交付全用这张长曝光,口径统一。学习率调度则是开车节奏:起步先热车(线性热身约 1 轮,小步试探),巡航后渐渐收油门(余弦回落)——既不熄火也不超速。

💡 大白话:拜师学艺

模型像位带眼力底子的新学员:前半段眼睛(冻结骨干)是名校预训练出来的,锁死不动;后半段大脑挂上小抄(LoRA)慢慢适应你家金属的样子;最后的"圈缺陷手法"(分割头)全新学、火力全开。每 100 训练步还会交一张"课堂作业"(采样图):输入切块 + 红框标出贴入缺陷的真实位置,供你在监控页抽查出题质量。

第 10 章

事件线 3C/D · 验证、考试与早停

对应 README 事件线 3[C][D] + §四.3「验证、考试与交付机制」+ trainer/exam 源码

10.1 val_loss:固定题集,固定尺子

每轮结束在验证集上算 val_loss:验证图按固定种子贴好同一批缺陷(EMA 权重、不增强),用全像素稠密口径(dense_masked_sums)算 Focal + 3×Dice——同一批题、同一把尺,跨轮分数直接比大小,无随机波动。为什么训练敢用 PointRend 挑着量、验证必须全像素?训练损失只需"推着进步",挑重点量反而高效;但 PointRend 被量的点随模型变化,跨轮不可比——验证特意换成全像素,而且口径有讲究:focal 按全部有效像素平均(含正常背景,专量误报倾向),dice 只按含缺陷的样本平均(纯净块的 dice 恒 ≈1,混进平均只会稀释信号)。

10.2 早停:练到进步停滞就收工

练满 8 轮(MIN_EPOCHS)后,val_loss 连续 4 轮(PATIENCE)不降(降幅需超 1e-4)即触发早停——防过拟合,也省时间。注意:早停只管"停不停",选型看的是考试总交集,不是 val_loss。

10.3 考试:整图推理 → 加权拼缝 → 交集计分

考试环节用到的具体技术:

  • 权重窗公式(blend_window):窗重 w = min(i/ramp, (ts−i)/ramp) 双向取小(ramp = 重叠带 128px),中心 1.0、块边趋 0;相邻两块在重叠带内权重此消彼长、和恒为 1(线性交叉淡入)——热力图在块缝处连续无缝;
  • 全程 GPU:整幅 1200 万像素图以 uint8 一次上显存(约 12MB),切块、归一化、推理、加权缝合、检测区清零全在显存完成,主机侧只一次上传一次取回;
  • 推理细节:bf16 自动混合精度 + sigmoid 概率化;输出尺寸与输入不齐时双线性插值兜底;标注多边形经 H⁻¹ 搬回基准系后用 fillPoly 栅格化,再与报警像素求交集;
  • 考前内存探针:垃圾回收 + 归还系统堆 + 清空显存缓存,并记录分配重试/OOM 计数——久训后考试变慢,先看这里;
  • 工程坑规避:多卡广播早停分数不走 torch 2.5.1 的 broadcast_object_list(NCCL 下有 bug),标量改用张量直传。
💡 大白话:圈红圈对答案

考试像批"圈红圈"的答卷:模型在考卷上圈红圈(报警像素),老师手里有标准答案(人工标注);分数 = 红圈与答案重合的面积——报得准、报得全才得高分;报多了不倒扣(但报警面积记在日志里供观察),报漏了直接丢分。前面那道"加权窗拼接"工序,就是为了红圈在图块接缝处不出现深浅突变。

🎯 阈值 0.5 为什么写死、不扫描调参?

交集随阈值单调变化——扫描选阈值必然滑向最低档(全不报警交集恒 0,或全报警虚高),毫无意义。固定 0.5,把"学得好不好"和"报多严"解耦:前者由训练负责,后者交付时一目了然(manifest 里 threshold 固定 0.5)。

10.4 存档与 best 选型

  • 逐轮存档:总交集 > 0 的轮,EMA 权重 + score.txt 存 .tmp/ep{轮}/(监控页柱状图数据源);每轮无论分数都覆盖一份 .tmp/latest/;
  • 唯一 best:总交集创新高才写 models/,新超旧删旧——models/ 里永远只有一个 best_int{交集}_ep{轮}.pth,文件名自带成绩与轮次;
  • 全程总交集恒为 0 → 不产 best,大声告警提示人工排查(逐轮权重还在 .tmp/ep*/ 里,可指定 --base 再练)。

第 12 章

监控网页与多卡并行

对应 README「启动训练与常用命令」+ main.py / web.py 源码

12.1 一条命令,双角色

uv run train 拉起的其实是常驻监控进程:自动开 http://服务器IP:8300 监控页(无鉴权,仅限内网),再孵出训练子进程跑完整事件线(状态写 .tmp/web)。训练结束后监控页继续存活,等重训/精调或 Ctrl+C;代码更新(git pull)后监控进程 exec 自我重启换新代码并自动拉起新训练——页面失联几秒后自动恢复,无需外部守护。

12.2 多卡并行(检测到几张显卡自动几张)

  • 各卡 DDP 并行训练,独立造题、种子不同(缺陷更多样);
  • 考试由 0 号卡独占执行,其余卡等待(避免重复计算,看门狗放宽到 60 分钟);
  • 对齐整图有 LRU 内存缓存:预算 =(可用内存 − 8G)× 0.6,由全部缓存持有者均分——同一张大图被它切出的几十个块反复读,缓存后每样本省一次 12MP PNG 解码(约 50ms);
  • 开训前先做考试算型暖机:用考试的两个极端批尺寸(16/8)走一遍 bf16 前向,固化算子计划,避免久训后考试首图冷启动卡顿。
💡 大白话

监控页就是班主任直播间:训练曲线、内存曲线、每轮考试柱状图、NG 图列表(标明谁是"从未训练的考卷"、谁是"借底图")、按需渲染的热力图,全在页面上围观;重训按钮 = 换新教材重开一局。

12.3 监控页的渲染机制与全工程技术栈

按需推理渲染(web.py 的 Renderer):页面想看哪张 NG 图,才装载对应权重现推一张全分辨率热力图;热力图内存缓存 3 张(每张约 49MB)——改报警阈值只重画描色、不重新推理;鼠标悬停读置信度用 8 倍降采样图(轻快)。状态跨进程传递靠 .tmp/web/ 下的文件(status.json 原子覆盖、曲线与告警逐行追加、成绩从各轮 score.txt 扫描);web 服务端是零依赖的标准库 http.server(多线程版)——不装任何 web 框架。
