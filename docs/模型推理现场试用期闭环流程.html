模型推理现场试用期闭环流程

发布上线 → 前期研发采集 NG 重标训练 → 相对稳定后业务标注误报/漏报 → 回流入池精调 → 考卷择优再发布，循环迭代直至指标达标转正式运行。

涉及工程：supervised_apps/train（训练引擎）· vision-ai-inference-v2（推理服务）· 误报/漏报标记工具（业务标注）。 流程图源文件 archify_field_trial_loop.json · 可独立打开完整交互图。

archify 交互图，顶部阶段带划分试用时间轴：① 上线准备 → ② 前期·研发重标 → ③ 稳定后·业务标注；主循环按顺时针阅读：上排发布与推理 → 右侧两阶段标注 → 研发/业务标注回流垂降入池 → 下排自右向左"入池 → 精调 → 择优" → 再发布回到起点；例外泳道为回滚与转正出口。

二、后续工作规划大方向

  1. 上线准备

    训练交付 models/{产品}/ → preflight 体检通过 → 整目录拷入推理服务（mtime 热更新，不重启）→ /detect 开跑，业务复核同步观察。

  2. 前期 · 研发主导积累

    研发人员按批采集现场 NG（复检确认的真实缺陷）与系统 NG（系统判定 NG，含误报）原图重标注：真缺陷标 NG、误报确认为 OK 负样本，入池精调重训、考卷择优后再发布，循环收敛；重标同时跟踪当前检测准确性（每批系统 NG 的误报占比、真实缺陷检出情况）——这既是收敛信号，也是切换业务标注的依据。

  3. 相对稳定后 · 业务接管标注

    误报/漏报率波动收敛、新增缺陷类型趋零即切换：业务人员复核 NG 逐件、OK 抽检，用标记工具在结果图上标注误报/漏报，走同一回流管线；研发转为入池质检与转化脚本维护。

  4. 转正运行

    误报率、漏报率、服务指标连续达标 → 转正式运行，人工复核降为低比例抽检；期间任何新版表现异常，旧版模型目录重拷即可分钟级回滚。

三、标注回流转化规则

标注类型处置落点（train 工程）
漏报缺陷新 NG 样本，部分抽作考卷训练池 *.bmp + .bmp.tmp；抽部分进 val/ 独立考卷
散发随机误报OK 负样本无 .tmp 入训练池
微小噪点误报先运维过滤再回流调 MIN_DEFECT_DIAMETER_MM（默认 0.5mm），无效再入池

两阶段同规则：前期系统 NG 复核同样按上表执行（真缺陷→漏报行，误报→对应误报行），仅执行人为研发。

四、关键纪律

两阶段切换

切换看收敛信号（连续若干批误报/漏报率收敛、考卷结果稳定）；切换后研发仍负责转化入池的坐标/格式质检，业务只管看图标注。

阈值与回流契约

线上坚持 manifest 0.5 阈值不现场调参；标注必须在原图坐标系、分辨率一致、每类 ≥4 实例（不足用 --reuse），转 .bmp.tmp 尽早脚本化。

只升不降 · 可回滚

新版 quality_score 对比线上版只升不降才发布；SUPERVISED_CKPT_DIR 侧按 {产品}_vN_bak 归档旧版，重拷即回滚。拷贝不得保留源 mtime。

度量与转正

全程记录误报率（NG 判定占比）、漏报率（OK 抽检占比）、lock_ms 与告警；建立版本台账（数据范围 + 发布时间 + 指标基线）支撑归因与回滚决策。

统计类工作

工作说明优先级
误报 / 漏报统计口径与报表定义分子分母（按件 / 按点位 / 按缺陷类型），数据源 = 复核标注记录 + DB 判定记录，产出按日 / 按批报表；漏报依赖 OK 件抽检，抽检比例需先定P0
准确性跟踪批报告将 eval.py qr 验收适配新 ckpt 布局（models/{产品}/），每批回流后出"DB 判定 vs 当前模型检出"对照报告——对应图中"重标+跟踪准确性"P1
版本台账每版模型记录权重名、quality_score、训练数据批次、发布时间、当期误报/漏报基线、preflight 结果；由 release 脚本自动追加，支撑只升不降与回滚归因P1
收敛判据量化把"相对稳定"写成数字（如连续 N 批误报率波动 < X%、新增缺陷类型为 0、考卷增幅收敛），作为切换业务标注的开关条件P2
转正评审数据包试用期周报 + 转正评审三指标汇总（误报率、漏报率、服务指标），从报表与台账汇总P2
可直接复用 · 不用新做

train 增量缓存（按批回流只处理新增图）；inference-v2 的 preflight + 热更新（缺的只是脚本化）；eval.py qr 验收与阈值扫描（仅需适配新模型布局）；产线 DB 记录链路（ai_check_records 及审核字段）。最短路径 = 回流转换脚本 + 发布/回滚脚本 + 现场环境 + 误报漏报报表四件事，其余边跑边补。
