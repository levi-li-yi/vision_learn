第 0 章

开场白:一个工厂的故事

对应原文 §一「项目定位」的背景铺垫
📖 先听个故事

想象你管着一条金属零件的质检产线。相机给零件拍照,你想让电脑自动找出照片里的瑕疵(行业黑话叫"缺陷",比如砂眼——金属表面的小坑、划痕——细长的刮痕)。

要教会电脑认缺陷,得给它看成千上万张"标好了哪里是缺陷"的照片。可现实很骨感:整批零件里可能就几张到几十张真有缺陷。老师傅只能对着这几张照片,把每个缺陷一小块一小块手动抠出来存成素材——又慢又累,还远远不够喂饱电脑。

synth_assets 就是为这件事而生的:把几十个真缺陷"裂变"成几百个长相不同、光影逼真的新缺陷素材,全自动,而且每个新素材都自带一张"哪里是缺陷"的精确标记图——电脑直接拿来学习,人工一个都不用抠。

🖼️ 看图基础

像素(pixel)图片由几百万个小方格拼成,每个方格叫一个像素,记录一个颜色。后面说的所有"图上的操作",本质都是在对这些小方格做数学。
灰度只论明暗、不管彩色的"黑白程度"。通常 0 = 最黑,255 = 最白。工业检测大多先把图转成灰度来分析。
.bmp 文件一种不压缩的图片格式,工业相机常用。画质无损、细节一根汗毛都不丢,代价是文件比较大。
掩码(Mask)和原图同样大小的一张"透明胶片":白色的地方(值为 1)表示"这里是缺陷",黑色的地方(值为 0)表示"这里不是"。像素级精准掩码= 精确到每一个小方格的对错判定。
二值图只有两种值的图(0 和 1,或 0 和 255)。掩码、形态模板存的都是二值图,像"剪纸模板"。
多边形标注(.bmp.tmp)用标注工具「老表,标我.exe」沿着缺陷边缘点一圈点、连成一个多边形,存进与原图同名的 .bmp.tmp 文件里,每条标注带个标签(label):「砂眼」「划痕」或「排除」。
外接矩形恰好能把一个图形完整框住的最小正方向矩形。Step 4 落盘时按掩码的外接矩形来裁小图。
底噪 σ(西格玛)干净金属上亮度的微小随机波动——像安静教室里的呼吸声。σ 是这股波动的"幅度统计值"(标准差)。后面 "3.5σ" 的意思是:比呼吸声大 3.5 倍才算真动静。

🤖 AI 绘图相关

模型 / 权重模型 = 一套会画图的"电子大脑";权重 = 大脑里亿万个数字旋钮。lora_weights.safetensors 就是存旋钮参数的文件。
FLUX.1-Fill-dev一个专业 AI 修图大模型(Fill = 填充/修复版),特长是"把图上指定的一块区域重新画一遍,且和四周衔接得天衣无缝"。black-forest-labs 公司出品,配置里那串 black-forest-labs/FLUX.1-Fill-dev 是它在 HuggingFace 模型库里的"门牌号"。
LoRA不动大模型本体,只在旁边外挂一小块"专项记忆补丁",专门学会画某一类缺陷。文件小、训练快,一类缺陷配一个。lora_rank 是补丁的"记忆容量"数字。
触发词(trigger_token)唤起 LoRA 记忆的"暗号"。画图时在提示里写上它(比如 [DEF_HT12_砂眼]),补丁才知道该掏出砂眼的画法。像上课点名,喊到才答"到"。
重绘(inpaint)AI 画图的基本功:把图上被掩码遮住的区域重新画出来,没遮住的地方一律不动。本文里说"AI 局部重绘"就是这事。
损失(Loss)给 AI 的画"打分扣分"的数字:画得越离谱分越高。训练就是一遍遍画、一遍遍扣分、一遍遍拧旋钮,让分数降下来。
bfloat16一种"小数位数少一号"的数字记法。精度略降但省一半显存、算得更快,是大模型训练的标配,FLUX.1 原生就用它。
显存 / A40显存 = 显卡上给 AI 计算用的"工作台面";A40 是 NVIDIA 的数据中心专业显卡(48GB 大显存)。"双 A40 服务器" = 装了两块 A40 的机器,笔记本跑不动,训练得靠它。
safetensors一种安全的模型参数保存格式(文件后缀名),比老格式不容易被塞恶意代码,业界现在都用它。
seed(随机种子)随机数的"起点密码"。固定它,同样的输入每次得到完全同样的结果——实验可复现全靠它。

🧩 图像处理手法

膨胀(dilate)把图形均匀"吹胖"几像素的操作。"外扩 8px"就是沿轮廓膨胀 8px。反义词是腐蚀(erode)(搓瘦)——OpenCV 的泊松克隆内部会偷偷往内腐蚀 4px,后文会专门提防它。
双线性插值旋转/缩放图片时,新位置的像素取它旁边 4 个像素加权平均来填,过渡平滑不生硬。
高斯柔化按"中间浓、四周淡"的钟形曲线把边缘轻微模糊,让 0/1 的硬边变成 0~1 的软渐变。
羽化让贴图的边缘从"完全不透明"平滑过渡到"完全透明",避免贴上去留一圈硬切边。"余弦羽化" = 按余弦曲线来滑,过渡特别顺。
弹性变形给图形叠加一张平滑的随机"位移场",每个点被推去方向不同、距离不同的位置——像揉橡皮泥,形状变了但风格没变。
差分两张图逐像素相减,变了的地方数值凸出来。玩过"大家来找茬"吗?两幅图叠在一起对比,不同处自动现形,就是这个原理。
大津法(Otsu)自动选"黑白分界线"的经典老办法,强行把画面按比例分成亮暗两半。缺陷很小、背景噪点多时会翻车(把噪点切成"缺陷")——所以本文改用"底噪倍数卡线"。
信噪比 / 峰值信噪比信号强度 ÷ 噪声强度,衡量"有多醒目"。峰值 = 最大那一处。本文规定:最大差值不到底噪的 3.5 倍,就判定"根本没画出缺陷"。
泊松融合(seamlessClone)OpenCV 的"无缝克隆":解一个泊松方程,把缺陷的明暗变化规律融进底图,让灯光、质感自然衔接——不是把贴纸硬拍上去,而是让缺陷"长"在金属上。
分桶(bucketing)训练时把同样尺寸的图凑成一批(batch)送进显卡。图片尺寸乱七八糟就得拆很多桶,批次对不齐、显存被切碎浪费(碎片化)。

🏗️ 工程协作

仓库(repo)/ GitLab仓库 = 一个项目的文件夹 + 完整的修改历史记录;GitLab 是团队存放仓库的平台(类似"带版本历史的团队网盘")。
CLI / uvCLI = 命令行界面,就是在黑窗口里敲命令。uv 是 Python 项目的快速安装运行工具,uv run synth ... 一条命令自动配好环境再启动程序。
JSON机器友好的数据格式:大括号 + "键: 值",一层层嵌套。不许写注释,专供程序读写。
JSONC允许写 // 和 /* */ 注释的 JSON,给人看的配置用——现场人员可以直接在文件里写备注说明。
manifest.json代码自动生成的"出厂铭牌",记录这个模型是给谁训的、怎么训的、用了多少样本。
.tmp/ 目录草稿目录:一切中间过程文件都丢这儿,随时整目录删除不心疼。gitignore = 声明"这些文件不进版本管理"。
原子化交付要么全部一次交齐,要么一件不发,绝不让半成品留在正式目录里。像快递"整箱签收",没有"先到半箱"这回事。
点位产线上相机拍照工位的编号,比如 JXFB-1-P1、JXFB-1-P5。一个产品通常有多个点位。
分区基准图上划出的区域定义(存于 {基准图名}.json),比如"加工面"——规定哪块区域是待检面,缺陷只允许出现在合法分区里。
⚠️ 两个最容易混的词

缺陷类型(砂眼、划痕)是"病种";点位(P1、P5)是"相机机位"。目录结构里两者都会出现,别搞混。

第 2 章

项目定位:synth_assets 到底解决什么问题?

对应原文 §一「项目定位:解决什么问题?」

痛点:两个"要命"

  1. 真实缺陷样本极少——只有几张到几十张。想教会电脑认缺陷,这个量远远不够。
  2. 人工抠素材太费劲——老师傅要逐个把缺陷从大图里抠出来,每抠一个缺陷要产出一对文件:
    • {名}.png:缺陷小图本体(从原图上裁下来的那一小块);
    • {名}_mask.png:同尺寸掩码图,标明小图里"哪几个像素是缺陷"。

定位:一座"缺陷素材裂变兵工厂"

原文给 synth_assets 的定位就一句话——"缺陷素材裂变兵工厂"。拆开念:

  • 裂变:一个变几百个。输入少量真缺陷,输出数百对形态各异的新缺陷素材;
  • 兵工厂:专门量产"弹药"(训练素材)的车间,不干别的;
  • 不改动现有训练架构:它不重复造轮子——"把缺陷贴到大图上"(大图贴图)和"训练分割模型"这两件事分别是 train 仓库的老本行,synth_assets 绝不抢活,只管把素材造出来。
💡 大白话

把 synth_assets 想成一家"缺陷照相馆":你交给它几只真砂眼当"模特",它先让 AI 画师学透砂眼长什么样(Step 2 训练),然后让画师换着姿势、换着光线拍几百张"艺术照"(Step 3 生成),拍完自动修片、自动裁剪、自动附上"缺陷在哪"的标记卡(Step 4),最后整整齐齐码进素材库,给下游的 train 仓库随取随用。

第 3 章

文件都放在哪?目录结构与格式规范

对应原文 §二「目录结构与文件格式规范」

一条铁律:人写的配置用 .jsonc,机器写的产物用 .json

三个仓库统一遵守这条规则,一看后缀名就知道这文件"谁负责维护":

文件类型扩展名规则说明典型文件
人工维护的配置.jsonc 允许编写 // 与 /* */ 注释,方便研发与现场人员维护说明 config/app_config.jsonc
datasets/{产品}/{点位}/assets.jsonc
代码生成的产物.json 标准纯 JSON(无注释),所有字段含义统一在仓库 README.md 中说明 {基准图名}.json(define_masks 产出)
models/.../manifest.json(synth_assets / train 产出)
💡 大白话

给人看的本子(.jsonc)可以随手写备注:"这行是干嘛的、现场别乱改";机器写的日志(.json)不需要注释,它的"说明书"统一放在仓库 README 里,查一处就够。

第二条铁律:正式产物进 models/,过程草稿进 .tmp/

这套产物管理逻辑与 train 仓库完全一致,新手只要记住"档案柜 vs 草稿纸"的比喻:

🗄️ models/{产品}/{缺陷类型}/ —— 正式档案柜

  • 只在 Step 2 LoRA 训练成功结束的那一刻统一生成,平时绝对干净;
  • 存放训练好的 LoRA 权重、形态模板库(templates/)与 manifest.json——都是正式可复用资产;
  • 以后想补造新一批素材?无需重新训练,直接加载档案柜里的权重,秒级生图。

🗑️ .tmp/{产品}/{缺陷类型}/ —— 草稿纸篓

  • 切图缓存、训练成功前的候选形状模板(1_crops/templates/)、重绘过程图、验收预览图……一切中间过程文件都丢这儿;
  • 随时可整目录一键删除,删了也能重跑出来;
  • 绝不污染源码、models/ 和 datasets/。

    • {点位}/:每个相机工位一个目录,里面三样东西——分区定义 json、人工维护的 assets.jsonc(写清"哪个分区绑定用哪类素材文件夹",通过 dir="../assets/..." 指过去)、原图 .bmp 与标注 .bmp.tmp(标注带「砂眼」「划痕」「排除」三种 label)。

第 5 章

Step 1 详解:样本切片与掩码准备

对应原文 §三 Step 1 + §四.1 前两行(外扩 8px / 固定 512 切片)

5.1 先分清:系统里有三种图,Step 1 切的是哪种?

新手最容易在这里犯迷糊:Step 1 切的不是人工抠的缺陷小图,人工抠的小图也不是 512。整个系统里其实同时存在三种图,各干各的活:

图的种类从哪来尺寸给谁用
点位原图 *.bmp工业相机拍的整幅大图很大(几千像素见方)原始素材来源
512 训练切片Step 1 从点位原图上裁的固定 512×512喂给 Step 2 训练 LoRA
素材小图(人工抠的 *.png、synth 产出的 synth/*.png)人工抠取 / Step 4 紧包裁剪不定的小尺寸(缺陷多大图就多大,四周留 8px)给 train 仓库泊松贴图用
  • 人工抠的缺陷小图是紧包着缺陷裁的小块,尺寸不固定、通常远小于 512——它们是给 train 当"贴图素材"用的,从头到尾不进 synth_assets 的流水线;
  • Step 1 干的是另一件事:回到点位原图(那幅大图)上,找到 .bmp.tmp 里标注的缺陷位置,以缺陷为中心从大图上裁出 512×512 切块,连同三区权重图送去训练 LoRA。
🎯 为什么教 LoRA 非得是 512?

① AI 画师只在固定尺寸的画布上干活:FLUX.1-Fill 这类模型要求输入固定分辨率的图块,512 就是它的工作分辨率,训练(Step 2)和生图(Step 3)都必须是这个尺寸;② AI 需要"周边环境"才能学会衔接:512 切块里缺陷只占中间一小块,四周全是正常金属——正因为带着这些背景(不算分但提供上下文),LoRA 才能学到"缺陷边缘怎么和金属过渡";③ 再加上两条工程理由:1:1 原生像素不缩放保锐度、尺寸统一不分桶不浪费显存(详见 5.5)。

💡 大白话:闭环的对称性

进去教 AI 的是 512 大块,最后产出来的仍是紧包小图(Step 4 按外接框 +8px 裁回去)——因为 train 要的还是和人工小图同格式的贴图素材。512 只是 AI 的"工作画布"尺寸,不是素材尺寸。

5.2 扫描归类:先清点家底

程序扫描 datasets/HT12/{各点位}/*.bmp.tmp,把标注按具体缺陷名归类——「砂眼」归砂眼堆、「划痕」归划痕堆,label 为「排除」的直接跳过(那些多边形是人工特意画了说"这块别管"的,比如反光的亮斑)。

5.3 轮廓外扩 8px:给 AI 留"过渡缓冲带"

把每个缺陷多边形顺着轮廓向四周形态学膨胀 8px(想象给图形均匀吹胖一圈),形成"内部核心区 + 8px 缓冲环带"的结构。

🎯 为什么是 8px?为什么顺着轮廓扩?

人工标注通常贴着缺陷边缘(顶多带几像素背景)。如果只让 AI 在原框里画画,AI 没有空间画缺陷边缘的立体暗影、毛刺、明暗过渡——画出来像一张"剪纸",死板、假。

顺着轮廓外扩 8px 就是给 AI 留出过渡带。关键在"顺着轮廓"四个字:因为是沿着形状扩(而不是扩成矩形框),一条细长划痕也只是两侧各加宽 8px,不会框进一大片无关背景。

5.4 生成三区权重图:一张"批改重点范围表"

在 512 切片上,每个像素被赋予一个 0~1 的训练权重,分成三个区:

区域范围权重含义
多边形内 · 核心区人工标注多边形内部1.0必须一比一学像
外扩 8px · 缓冲带多边形外圈 8px 环带1.0 → 0.4 渐变越靠近缺陷越重要,向外逐渐放松
缓冲带外 · 背景区其余全部0.0完全不管,学不像也不扣分
💡 大白话

三区权重就是老师批作业时拿红笔圈的范围:圈内(1.0)必须批,圈边(0.4~1.0)顺手批轻点,圈外(0)压根不看。这样 AI 不会被"背景长啥样"分走任何注意力。

5.5 固定 512×512 切块:以缺陷为中心裁训练图

所有训练与重绘统一按 512×512、1:1 原生像素、不缩放裁剪;切块以缺陷为中心,但带轻微随机偏移——为了避开同图上的其他缺陷,别把两个缺陷裁进同一块。

🎯 为什么死守 512×512 不放?

原文给了三条硬理由:

  1. 保锐度:1:1 保持工业相机原生像素,细微缺陷(细划痕、小砂眼)不因缩放而糊掉;
  2. 保显存:尺寸统一就不用"多尺寸分桶",训练批次能对齐,显存不被碎片化浪费;
  3. 保对齐:与下游 train 仓库的切块尺度(512)完全一致,无缝衔接。
💡 大白话:一图一掩码一缺陷

每张 512 切片只认一个"主角"缺陷——同图若还有别的缺陷被裁进框里,它在训练掩码里权重置 0、像素抹平成正常金属(当作不存在)。为什么这么较真?LoRA 一次只该学一个缺陷的画法,放两个进来,它可能学会"一次画俩"——主角光环必须独一份。

5.6 Step 1 的产物去哪?

训练切片、三区权重图、候选二值轮廓模板(templates/)、切图预览拼图——全部写入 .tmp/HT12/{缺陷类型}/1_crops/,此时一个字节都不写 models/(正式档案柜必须等 Step 2 训练成功才开柜)。

第 6 章

Step 2 详解:缺陷资产 LoRA 训练

对应原文 §三 Step 2 + §四.1 第三行(三区软权重损失 / 成功后统一转正)
⚠️ 在哪跑?

这一步和 Step 3 都标注了「在双 A40 服务器执行」——训练大模型要吃大量显存,开发笔记本带不动,得靠装了两块 A40 专业显卡的服务器。

6.1 登场的三位主角:画师、笔记、暗号

讲"训练"之前,先把这一步登场的三个角色认熟。一句话记住它们的关系:FLUX 是画师,LoRA 是外挂在他身上的专项笔记,触发词是点名暗号。

  • FLUX.1-Fill-dev(画师本体):专业 AI 修图大模型,以 bfloat16 原生精度加载(省一半显存、算得快,这也是它原生使用的精度);
  • LoRA(专项笔记):不动画师本体,只在旁边外挂一小块"砂眼画法"记忆;一类缺陷配一本笔记,lora_rank 32 = 笔记的容量;
  • 触发词(点名暗号):比如 [DEF_HT12_砂眼]——生图时在提示里喊它,笔记才被激活、画师才按笔记画。
🎯 为什么只训 LoRA,不动 FLUX 本体?

① 手头只有几十张真实样本,拿这么少的数据去硬改几十亿参数的大模型,极易把画师"教坏"(行话叫学崩、把原会的都忘了);② 全参数训练需要海量数据和惊人显存,不现实;③ LoRA 参数少,小数据就能学会专项,还一类缺陷一本、即插即拔——要训划痕就再挂一本"划痕笔记",砂眼笔记毫发无伤。

6.2 AI 是怎么"画"出来的:从噪点里一步步"擦"出图

这类 AI(扩散模型)的画法和人类画家正相反:不是从白纸上一笔笔加,而是从一团随机噪点起步,一步步把噪点擦掉——图像像显影液里的照片、像雾里走出来的人,渐渐浮现。

FLUX.1-Fill 版就在这条去噪之路上多了一门绝活:它的输入除了噪点起点,还有一张现成的图 + 一个"洞"(掩码)——它只重画洞里的内容,并且强制与洞四周的纹理、明暗接茬。这和我们的任务严丝合缝:"在一块完好的金属上,补出一个以假乱真的缺陷"。

💡 大白话

Fill 版就像修图软件里的"修补画笔":圈住哪里重画哪里,边缘自动融进周围——只不过它不是复制别处的像素,而是凭笔记"想象"出一个砂眼画上去。

6.3 训练 = "画 → 比 → 改"循环一千遍

所谓训练,就是让这位挂着笔记的画师反复应考、反复订正,每轮四拍:

💡 大白话:蒙眼下山

训练像蒙眼下山——损失是海拔,旋钮是走路方向。每走一步(画一张、比一次)就感觉脚下是上坡还是下坡(损失变大还是变小),朝下坡方向微调再走。学习率 1e-4 = 每步只迈 0.0001 格:步子太大容易一步跨过谷底(学崩),太小又走不到(学不动);1000 步(train_steps)= 这座山总共允许走一千步,第 1000 步停下时的旋钮位置,就是最终存档的 LoRA 笔记。

6.4 掩码加权损失:只考重点章节

训练时给 AI 的画打分(算损失),但分数要按三区权重加权:

  • 核心区(权重 1.0)与缓冲带(权重 0.4~1.0):计入生成误差——画不像就狠狠扣分;
  • 外部背景(权重 0.0):不计入损失——背景画成什么样,一分都不扣。
🎯 为什么把框外权重设成 0?

逼迫 AI 把 100% 的算力用来学两件事:"这类缺陷长什么样" 和 "缺陷边缘怎么和周围金属衔接过渡"。背景是山是水与它无关,注意力一克都不浪费。

6.5 原子化交付:训练成功才开档案柜

训练未成功时,一切产物都以"候选"身份躺在 .tmp/ 草稿区;只有训练成功结束的那一刻,程序才把三样东西一次性整包写入 models/HT12/{缺陷类型}/ 正式档案柜——要么三件齐,要么一件都不出现:

开柜交付的"三件套"到底是什么?

交付物到底是什么里面装什么以后谁用它、干什么
lora_weights.safetensors

💡 大白话:为什么三件必须绑在一起?

光有权重没模板 → Step 3 没有形状底坯,新缺陷形状会跑偏;光有模板没权重 → 画师没学会画法,画不逼真;没有铭牌 → 日后没人说得清这套资产的来历。三件互相配套,缺一件整包就不可用——所以干脆"要么整箱到货,要么一件不发"。

🎯 为什么要"原子化"?

训练未成功前,models/ 目录保持绝对干净——绝不出现"有权重没模板"或"有模板没元数据"的半成品。只有训练成功结束,才一次性产出完整可用的模型包(权重 + 形态模板 + 元数据)。像快递整箱签收,没有"先到半箱"。

💡 大白话

Step 2 像给一位本来就会画画的大师傅(FLUX)报了个"砂眼专修班"(LoRA):只给他看砂眼的照片(核心区 1.0),顺便看看砂眼和金属怎么接茬(缓冲带 0.4~1.0),完全不考背景静物(0 分权重)。结业那天(训练成功),他的"砂眼笔记"连同教材范本(模板)和结业证书(manifest)一起归档进档案柜。

第 7 章

Step 3 详解:掩码裂变与局部重绘

对应原文 §三 Step 3 + §四.1「真实模板弹性变形」「合法分区采样 + 框外零篡改」

从这一步起进入"量产"阶段,四个动作一气呵成:裁干净底图 → 捏新形状 → AI 画缺陷 → 羽化回贴。

7.1 裁干净底图 P_clean:从合法分区里挑一块"无瑕白布"

  • 只在点位图 合法的检测分区内取材(分区定义来自 {基准图名}.json,比如只允许在「加工面」里放缺陷);
  • 随机位置裁 512×512 的干净金属块(记作 P_clean);
  • 裁的时候避开已有的 .tmp 标注区——别把真缺陷裁进来当底布。
🎯 为什么非要从"合法分区"里裁?

保证生成的缺陷,它的底座纹理就是该产品真实待检面的材质纹理。在加工面上训练出的砂眼,贴到非加工面就假了;底布必须来自"缺陷真正会出现的地方"。

7.2 捏新形状:揉橡皮泥式弹性变形

从 models/HT12/{缺陷类型}/templates/ 抽取真实缺陷轮廓,然后:

  • 随机旋转 / 翻转 / 缩放:换个朝向、镜像一下、放大缩小;
  • 弹性扭曲变形:叠加一张二维平滑随机位移场,把轮廓推得歪歪扭扭又自然;
  • 变形后的轮廓经 Halcon 单应对齐投射(蒙版精准对位到当前底图坐标)后再外扩 8px,得到重绘粗框 M_local——且其外接框必须 100% 落在检测区内(整框入区)。
🎯 为什么要用真实模板"揉",而不是凭空随机画?

直接随机画,形状可能根本不像这类缺陷。以真实轮廓为基底做弹性变形,既保留该类缺陷的物理形态规律(砂眼的凹凸锯齿感、划痕的细长弧度),又保证生成的几百个新缺陷没有两个形状完全雷同——多样性和真实性兼得。

💡 大白话:印章先对位,再盖章

变形后的"印章"不是直接拍上去:先用 Halcon 单应投射把蒙版精准对位到当前底图坐标(与 train 工程对齐同款技术),并且整个粗框都必须落在检测分区内(整框入区)——这样落盘小图四周的 8px 边距才是 100% 纯金属,绝不混入黑孔等检测区外内容。

7.3 AI 局部重绘:挂上 LoRA 开画

挂载该缺陷的 LoRA(把 Step 2 训好的专项笔记插到 FLUX 画师身上)之后,还要凑齐三样"派工输入",AI 才开工:

  • ① 画布:P_clean,512×512 干净金属块(7.1 裁的);
  • ② 洞(在哪画):粗框 M_local——7.2 捏好形又外扩 8px 的重绘范围;
  • ③ 派工单(画什么):文字提示 + 触发词 [DEF_HT12_砂眼],点名唤醒 LoRA 笔记。

画法就是 6.2 讲过的"从噪点里擦出图",只不过 Fill 版把"擦"的动作限制在洞内:洞内的噪点一边参考洞外的纹理、一边按 LoRA 笔记的画法渐渐显影成缺陷;洞外像素从头到尾一个不碰。

💡 大白话:像给装修队派单

房子在哪(画布 P_clean)、只刷哪面墙(洞 M_local)、刷成什么风格(提示词 + 触发词点名"砂眼笔记")——三样写清楚,装修队(FLUX + 挂载的 LoRA)进场只刷指定的那面墙,屋里其他地方绝不乱动。

7.4 无损羽化回贴:只动框内,框外一根毫毛不伤

  • 把画好的区域贴回 P_clean 时,粗框边缘向内 4px 做余弦羽化融合——边缘透明度按余弦曲线平滑滑落,没有硬切缝;
  • 框外像素 100% 保持 P_clean 原样,得到最终成品图 P_final。
🎯 为什么"框外零篡改"是死规矩?

这是给下一步(前后相减自动抠图)埋的伏笔:既然框外像素和 P_clean 一字不差,那么两张图逐像素相减时,框外差值必然是 0——"哪里变了"就等于"缺陷画在哪",全自动抠图才有可能成立。

过程文件都缓存在 .tmp/{产品}/{缺陷类型}/2_inpaint/(重绘前干净底图 + 重绘后对比),随时可翻看、可整目录删除。

第 8 章

Step 4 详解:前后差分自动抠图与导出

对应原文 §三 Step 4 + §四.1 后三行(差分提纯 / 底噪双阈值 / 紧包导出)

8.1 前后相减:玩一局"大家来找茬"

拿【画完缺陷的图 P_final】减去【画之前的干净底图 P_clean】,对每个像素算 |P_final − P_clean|——同时看灰度差和纹理梯度差(纹理梯度 = 局部纹路变化的剧烈程度,专抓"亮度没变但纹路变了"的情况)。

💡 大白话 + 原文的数字例子

给 AI 的重绘框是带缓冲带的宽框:比如框有 20px 宽,AI 在中间画了条 5px 宽的真划痕,两边各 15px 被 AI 补成了正常金属。前后相减后——补成正常金属的地方差值接近 0,直接抵消归零;只有真正长出缺陷的那 5px 差值巨大。于是无需人工抠图,全自动提纯出精准的 _mask.png。

8.2 底噪自适应卡线:按"背景吵不吵"定及格线

差分图有了,还差一条"多亮才算缺陷"的分界线。做法分两步:

  1. 先测底噪:量出框外正常金属的底噪波动 σ(干净区域的"呼吸声"有多大);
  2. 再双阈值卡线:
    • 差值 > 3.5σ → 判为缺陷核心(比呼吸声大 3.5 倍,肯定是真动静);
    • 再把核心周围 > 1.8σ 的相连像素吸纳进掩码(缺陷边缘的阴影过渡,暗一点但和核心连着,也要)。

两步合起来,得到像素级精准掩码 M_GT——它就是落盘的 {名}_mask.png。

💡 大白话:监考老师抓说话

把一张差分图想象成一间上自习的教室,程序就是监考老师,分两步:

  1. 先摸清"这间屋的安静"有多响:教室从来不是绝对无声——呼吸、翻页、椅子吱呀,总有个稳定的背景响度,这就是底噪 σ。要测就去保证没人讲话的角落测——对应"框外正常金属"(那里确定没被 AI 动过,基准才可信);
  2. 再按现场定及格线,不拍脑袋定死:比日常吵闹响 3.5 倍的,铁定有人在说话 = 缺陷核心;1.8 倍以上、又从说话人那边连过来的"余音" = 缺陷边缘,也算他一部分;孤零零一声椅子响,哪怕过了 1.8 倍也不算——不相连,不冤枉。
🎯 为什么两条线,还死抠"相连"?

只用高线 3.5σ:缺陷边缘的暗影过渡会被切掉,掩码偏小——像只框到说话人的嘴、丢了半张脸;只用低线 1.8σ:背景噪点大量混入,掩码长毛。高线定核心、低线只收"连着核心的",两头的好处都拿到;而"不相连就不收"保证了孤立的椅子响(噪点)永远冤枉不到人。

💡 "自适应"到底自适应在哪?

不同教室的安静程度天差地别(图书馆 vs 车间旁的教室)。每一张图、每一个框都现场重测一次 σ,及格线跟着现场走:反光强、底噪大的产品,线自动抬高;干净细腻的产品,线自动放低——不管背景吵不吵,"超过 3.5σ 就是核心"这条规则永远成立。

🎯 为什么不用教科书常用的大津法(Otsu)?

大津法会强行把画面按比例分成亮暗两半。遇到微小缺陷(比如 3×3 像素的小砂眼),缺陷只占画面一丁点,大津法为了"凑够两半"会把整圈背景噪点都误判成缺陷。

按背景底噪倍数卡线就没这个问题:不管缺陷多大或多小,只要真画出来了,差值一定远超底噪,就能精准抠出。另外它还自带"废片探测器"——若全框差值都没超过 3.5σ,说明压根没画出缺陷,直接进下一节的质量门控淘汰。

8.3 质量门控:不合格的废片直接扔

抠出来的结果要过两道检查,任何一道不过就判定为"未成功画出缺陷"的废片,自动丢弃重画:

一张画完的 512×512 图(P_final)
↓
检查 ①:抠出的缺陷面积够大吗?(过小 = 没画出来)
↓
检查 ②:峰值信噪比 ≥ 3.5 吗?(最大差值 ÷ 底噪 σ,不够醒目 = 假缺陷)
↓
✅ 通过 → 紧包裁剪、落盘入库
❌ 任一不过 → 判定废片,自动丢弃、重新画一张

8.4 紧包裁剪落盘:切小图、留边距、写素材库

在 512×512 图上抠出精准掩码 M_GT 后,按 M_GT 的外接矩形、四周各留 8px 边距裁出缺陷小图,写入 datasets/HT12/assets/{缺陷类型}/synth/{序号}.png + {序号}_mask.png——一对成品素材就此诞生。

💡 大白话:切出来多大?不是 512!

512×512 只是 AI 的工作画布(训练、重绘、差分都在上面进行),落盘的是从画布上"紧包"裁下来的小图:缺陷多大,图就多大,每张小图尺寸都不一样。为什么不带着大片金属一起存?下游 train 是"把小缺陷贴到大图随机位置"训练的,素材只要缺陷本体加一圈边距就够;而且人工抠的素材也是这个紧包格式,对齐了才能零修改无缝调用。

第 9 章

掩码的一生:从人工标注到训练标签的完整闭环

对应原文 §四.0「从 0 到 1 轮廓(Mask)全生命周期操作时间线(速查表)」

这是全文技术含量最高的一节。掩码(缺陷轮廓)从人工画出来的那一刻起,一路经历变身,直到变成训练标签。原文用一句话概括它的一生:

💡 一句话的一生

紧贴标注 → 外扩留过渡带 → 差分收紧提纯 → 落盘留余量 → 内存抹平背景 → 外扩送入泊松 → 按原掩码柔边回写并打标签

翻译:先贴身画(0px)→ 为了教 AI 和给 AI 留缓冲,胖一圈(+8px)→ 画完后靠差分把虚胖瘦回去(收紧成 M_GT)→ 存盘时四周留余量(+8px 边距)→ 进 train 后先把素材背景抹干净 → 送进泊松前又胖一圈(+5~7px,防被内部腐蚀吃掉)→ 但写回底图和打标签都只认没胖过的原掩码(柔边 m_float)。

人工标注老表,标我.exe · 标注 .bmp.tmp

做了什么:用标注工具「老表,标我.exe」紧贴真实缺陷边缘画多边形,不外扩(0px)。

为什么:确立最原始、最老实的真实缺陷几何边界 M_raw——记在原图原生坐标系,天然零偏移,后面一切变形都以它为基准。

LoRA 切片(一分为二暂存)synth_assets · Step 1 & 2

做了什么:在 512×512 切片上按「一图一掩码一缺陷」拆两份暂存 .tmp/1_crops/——每张切片只装一个缺陷:

  • 原多边形直接转二值图 → 存 .tmp/.../templates/(0px,保持原样;Step 2 训练成功后随 LoRA 转正进 models/);
  • 训练权重图 → 只给当前这一个缺陷顺轮廓固定外扩 +8px:核心 1.0、环带 1.0→0.4、外部 0;同块若带入相邻缺陷,其权重一律置 0、像素抹平成正常金属(即第 5 章的三区权重图)。

为什么:存 templates/ 是为了保留真实缺陷的原始骨架(给 Step 3 当变形底坯);训练权重外扩 +8px 是为了让 LoRA 学会缺陷边缘与周围金属的过渡衔接;而严格单缺陷掩码,是杜绝 LoRA 学会"一次画两个缺陷"——一次只教一招。

对齐重绘与落盘synth_assets · Step 3 & 4

做了什么(三个时刻):

  • 重绘前:取 models/.../templates/ 的轮廓做弹性变形 → Halcon 单应对齐投射蒙版(把蒙版精准投到当前底图坐标)→ 外扩 +8px 得粗框 M_local,且要求 M_local 外接框 100% 落在检测区内,再交给 AI 画缺陷;
  • 重绘后:前后相减(|P_final − P_clean|)按底噪倍数把掩码收紧回真实长出的缺陷边缘 M_GT——它就是落盘的 *_mask.png;
  • 裁小图落盘:按 M_GT 外接矩形向外留 +8px 边距,裁出 *.png 与 *_mask.png。

为什么:重绘前扩 +8px 是给 AI 留融合缓冲;单应对齐 + 整框入区,保证落盘小图四周的 8px 边距全是纯金属——绝不混入黑孔等检测区外内容;重绘后差分收紧是为了剥离被 AI 填成正常金属的边框(虚胖部分差值≈0,自动消失);裁小图留 +8px 是让 *_mask.png 四周有一圈金属背景余量,供下游泊松外扩使用。

训练加载与旋转train · assets.py + dataset.py

做了什么:

  • 内存抹平背景:读取小图配对进内存时,先把 ~mask 区域(掩码外)填平为外圈背景中值(一圈干净的平均色);若 mask 贴着小图边缘,自动向四周补 1px 背景边;
  • 随机缩放与旋转:图像用双线性插值;mask 经插值 + 1px 高斯柔化,得到 0~1 的浮点掩码 m_float。

为什么:先抹平 ~mask 背景,防止素材原图里的异物或条纹被带进新底图;补 1px 边是防止 0~360° 随机旋转时边界复制拉出三角伪影(旋转算法在图边缘没像素可取时会复制边上一行,斜着旋转就拉出难看的三角条纹)。

泊松贴入与打标签train · paste_poisson

做了什么(严格三步):

  1. 掩码外扩送泊松:把 m = (m_float > 0.4) 二值化后外扩 +5~7px(贴边则自动补边),送入 cv2.seamlessClone(NORMAL_CLONE) 解泊松方程;
  2. 原掩码柔边回写:仅按未外扩的 m_float(1px 柔边),把泊松调光后的缺陷软混合写回底图,再按检测区边界将区外截断——锚点靠边时故意跨边贴入、齐边截断,天然制造贴边缘的"塌边"缺陷样本;
  3. 打训练标签:按未外扩的 m_float > 0.25 且∩ 检测区,标为缺陷正样本 1(区外不算)。

为什么(对应三步):

  • OpenCV 泊松内部会强行向内腐蚀 4px——不先外扩 5~7px,缺陷最外圈的梯度细节就被"吃"掉了;
  • 按未外扩的 m_float 回写,保证缺陷本体以外 100% 不破坏底图原有纹理(外扩那圈只是给泊松方程当"工作间",不是成品的一部分);
  • 监督标签收紧到 m_float > 0.25,避免模型把外扩背景学成缺陷、导致预测框发胖。
底图已有真缺陷屏蔽train · _annot_tile

做了什么:底图 .bmp.tmp 上已有的真缺陷多边形,向四周外扩 +4px(常量 ANN_DILATE = 4),标为 255(忽略区,不计 Loss)。

为什么:人工标注紧贴缺陷,但缺陷边缘往外还有几像素过渡带(半黑不白的像素)。不设忽略区的话,这些过渡像素会被当成"正常背景 0"教给模型,把模型教糊涂;外扩 +4px 设为忽略区(不奖不罚),模型就不用对这条模糊地带表态。

第 10 章

设计问答:8 个"为什么非这么设计不可"

对应原文 §四.1「synth_assets 各阶段核心设计说明」——每行设计的"怎么做 + 为什么"全部收录
💡 大白话

前面章节边讲边解释过一部分"为什么",本章把原文设计表里的 8 个设计决策原原本本集中成问答,方便你检验自己是否真看懂了。每条都能在对应章节找到展开。

Q1 · 为什么顺着多边形轮廓外扩 8px,而不是让 AI 在原标注框里画?(Step 1)

怎么做:将 .tmp 中的缺陷轮廓多边形向四周形态学膨胀 8px,形成"内部核心区 + 8px 缓冲环带"。

为什么:人工标注通常贴着缺陷边缘(或略带几像素背景)。如果只让 AI 在原框内画画,AI 没空间画缺陷边缘的立体暗影、毛刺或明暗过渡,画出来像剪纸。顺着轮廓外扩 8px 给 AI 留出过渡带;且因为是顺着轮廓扩(非矩形框),长划痕也只是两侧加宽 8px,不会框入多余背景。

Q2 · 为什么所有图统一固定 512×512 切片?(Step 1)

怎么做:所有训练与重绘统一按 512×512(1:1 原生像素,不缩放)裁剪。

为什么(三条):① 保持 1:1 工业相机原生锐度,不因缩放模糊细微缺陷;② 避免多尺寸分桶导致训练 Batch 无法对齐和显存碎片化;③ 与下游 train 仓库的切块尺度(512)完全一致。

Q3 · 为什么用三区软权重损失,还非要"训练成功才转正"?(Step 2)

怎么做:核心区权重 1.0、外扩 8px 缓冲带权重 1.0→0.4、框外权重 0.0;仅当 LoRA 训练成功完成时,才把权重与 .tmp/1_crops/templates/ 一起写入 models/。

为什么:① 框外权重设为 0,逼迫 AI 把 100% 算力用来学"缺陷长什么样"及"缓冲带怎么和周围金属衔接";② 训练未成功前 models/ 目录保持绝对干净,只有训练成功结束才一次性产出完整可用的模型包(权重 + 形态模板 + 元数据)。

Q4 · 为什么新形状要拿真实模板做弹性变形,而不是随便画?(Step 3)

怎么做:取真实缺陷轮廓做任意角度旋转、缩放,并叠加二维平滑随机位移场扭曲轮廓,再外扩 8px 作为重绘框。

为什么:既保留该类缺陷真实的物理形态规律(砂眼的凹凸锯齿感、划痕的细长弧度),又保证生成的几百个新缺陷没有两个形状完全雷同。

Q5 · 为什么底图必须从合法分区里裁,且框外零篡改?(Step 3)

怎么做:只在点位 {基准图名}.json 允许的检测分区(如「加工面」)内取干净底图,重绘后仅更新粗框内部像素。

为什么:保证生成的缺陷底座纹理就是该产品真实待检面的材质纹理;且重绘框外 100% 像素零改动,为下一步"前后相减自动抠图"提供绝对干净的基准。

Q6 · 为什么要前后相减(差分提纯)?(Step 4)

怎么做:拿【画完缺陷的图 P_final】减去【画之前的干净底图 P_clean】。

为什么:给 AI 的重绘框是带缓冲带的宽框(例如 20px 宽),AI 在中间画了 5px 宽的真划痕,两边 15px 被 AI 补成了正常金属。前后相减后,补成正常金属的地方差值接近 0,直接抵消归零;只有真正长出缺陷的那 5px 差值巨大——从而无需人工抠图,全自动提纯出精准的 _mask.png。

Q7 · 为什么按"背景底噪倍数"双阈值卡线,而不用大津法?(Step 4)

怎么做:先算框外正常金属的底噪波动 σ;规定差值 > 3.5σ 为缺陷核心,再把核心旁 > 1.8σ 的相连像素吸纳进掩码。

为什么:传统 Otsu(大津法)会强行把画面按比例分两半,遇到微小缺陷(如 3×3 小砂眼)会把整圈背景噪点误判为缺陷。按背景底噪倍数卡线,无论缺陷多大或多小,只要真画出来了就能精准抠出;若全框差值都未超过 3.5σ,还能自动识别为生成失败的废片并直接淘汰。

Q8 · 为什么按精准掩码外接框(+8px 边距)裁成小图?(Step 4)

怎么做:在 512×512 上抠出精准掩码后,按掩码外接矩形(四周留 8px 边距)裁成小图存入 assets/{类型}/synth/。

为什么:下游 train 仓库需要紧包缺陷的小图配对;四周留 8px 边距与 train 泊松融合前外扩 5~7px 遥相呼应,确保外扩时有充足的背景余量。

12.1 config/app_config.jsonc(人工维护 · 支持注释)

全流水线的"总设置面板"。原文文件长这样(// 注释是它相比 .json 的超能力):

{
  // 切块与重绘分辨率 (固定 512×512, 1:1 原生像素不缩放)
  "tile_size": 512,
  // 缺陷多边形轮廓固定外扩像素数 (缓冲带宽度)
  "mask_dilate_px": 8,
  // 基座模型路径或 HuggingFace ID
  "base_model": "black-forest-labs/FLUX.1-Fill-dev",
  // LoRA 训练默认参数 (双 A40 bf16)
  "lora_rank": 32,
  "train_steps": 1000,
  "learning_rate": 1e-4,
  // 每类缺陷默认合成目标数量
  "synth_count": 200,
  // 差分抠图信噪比阈值: 核心区高阈值 / 边缘吸附低阈值
  "snr_high": 3.5,
  "snr_low": 1.8,
  // 导出小图四周保留边距 (供下游 train 泊松外扩 5~7px 使用)
  "export_pad_px": 8,
  "seed": 20260927
}
字段值大白话解释
tile_size512切块与重绘的统一分辨率。512×512、1:1 原生像素、绝不缩放(原因见第 5 章 Q2)。
mask_dilate_px8缺陷轮廓固定外扩的像素数,即"缓冲带宽度"。全文反复出现的那个 8px 就是它。
base_modelFLUX.1-Fill-dev基座大模型的路径或 HuggingFace ID——AI 画师的"本体",Step 2 训练、Step 3 生图都基于它。
lora_rank32LoRA 的"记忆容量"。越大记得越细但文件越大、训练越慢,32 是平衡点。按双 A40 + bf16 的默认训练参数设定。
train_steps1000训练步数:把训练素材翻来覆去学多少轮迭代。1000 步对几十张图的专项学习足够。
learning_rate1e-4学习率 = 每步"拧旋钮"的幅度(1e-4 就是 0.0001)。步子太大会学崩、太小会学不动。
synth_count200每类缺陷默认要合成多少个新素材(命令行 --count 可覆盖它)。
snr_high3.5差分抠图的核心区高阈值:差值超过底噪的 3.5 倍才认定为缺陷核心。
snr_low1.8边缘吸附低阈值:核心旁差值超 1.8 倍且相连的像素,吸进掩码当边缘。
export_pad_px8导出小图四周保留的边距。专门为下游 train 泊松外扩 5~7px 留的余粮。
seed20260927随机种子:固定它,同样配置每次跑出完全同样的结果,实验可复现、问题可排查。
